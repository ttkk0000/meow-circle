## 1. 武汉／上海首发双城分物种 × 行为准入矩阵（`LC08`）

### 1.1 物种白名单与全平台绝对红线

1. **猫咪（核心物种，优先级 P0）**：家猫及常见伴侣猫品种均可建档、发日常、发互助、送养或合规出售/有偿转让。
2. **犬类（友好物种，优先级 P1）**：遵守首发城市养犬管理条例。日常交流、走失拾获、领养与合规出售均须满足所在城市狂犬病强制免疫与养犬登记（犬证/电子标识）规则。
3. **其他允许伴侣物种（扩展物种，优先级 P2）**：仅限**家兔（兔兔）、仓鼠、豚鼠（荷兰猪）、龙猫（毛丝鼠，人工繁育伴侣品系）**等常见非保护类家庭伴侣小宠，支持建立独立宠物档案、日常日记、同城互助与无偿送养；商业售卖须具备合法经营范围与检疫/来源说明。
4. **全平台绝对禁入红线（一票否决，触发直接拦截与安全复核）**：
   - 严禁发布任何国家重点保护野生动物、CITES 附录管制物种、三有保护野生动物及外来入侵物种（如薮猫、狞猫、耳廓狐、猴类、未经特许的爬行/异宠等）。
   - 严禁在武汉、上海城市区域发布当地《养犬管理条例》明令禁止个人饲养的**烈性犬、大型攻击性犬种**（如藏獒、比特斗牛梗、斯塔福梗、阿根廷杜高犬、巴西非拉犬、日本土佐犬、意大利卡斯罗犬等及上述血统杂交犬）的领养、出售或有偿转让信息。
   - 严禁发布无合法《动物防疫条件合格证》或《检疫证明》的跨省/跨城批量活体拼车兜售、盲盒活体快递或活体抽奖信息。

## 2. 四方标准业务协议核心条款草案（`LC09`）

> **设计原则：** 平台当前阶段（MVP R1）定位为**社区交流、领养对接与看宠预约信息服务平台**，不代收活体交易款项、不提供资金托管或医学健康担保。以下四份标准条款嵌入端内对应确认流与 `ruleDetail` 独立阅读页，每次申请、预约或交接确认时，系统将双方勾选确认的协议版本号写入不可覆盖的业务快照（`Snapshot`）。

### 2.1 《M&D 无偿领养与爱心交接确认协议（草案 v1.0）》

- **适用场景**：救助方/个人送养人与领养申请人确认正式交接（`handover_pending → confirmed`）。
- **核心条款要点**：
  1. **信息真实与关系透明**：送养方确认其对涉事宠物享有合法送养处分权或已获原救助/照护主体明确授权，已如实披露目前已知的健康、免疫、绝育及行为习惯，未隐瞒已知重大传染性疾病。
  2. **无偿性质与合理分摊边界**：本通道为爱心领养。除发布页及预约快照中已预先公示、且附有真实医院/机构凭据的合理医疗支出分摊外，送养方不得在交接现场或交接后追加索取任何活体买断费、无凭据押金、强制猫粮/用品套餐或金融分期。
  3. **科学照护与回访配合**：领养人承诺具备与申请表一致的合法饲养条件（犬类须遵守武汉/上海当地《养犬管理条例》办理免疫与养犬登记），提供必要科学喂养与医疗照护，不遗弃、不虐待、不将领养宠物转卖或用于商业繁殖，并配合约定的 30 天站内私密回访（默认仅双方与平台必要复核可见，未经领养人另行授权不得公开家庭环境与个人信息）。
  4. **不可过度索赔与禁止非法侵入**：双方不得在私下补充协议中约定明显失衡的高额惩罚性违约金、人身控制条款或未经同意强行入户搜查条款；发生争议时优先通过平台证据链与依法途径解决。
  5. **异常退出与安全接回（`SC-AD`）**：若领养后确因不可抗力、严重过敏或家庭重大变故无法继续饲养，领养人必须第一时间通过平台发起“退养与安全接回求助”，联系原送养方协商接回或重新匹配，严禁私自遗弃、放生或转售。

### 2.2 《M&D 单宠独占试养与安全接回协议（草案 v1.0）》

- **适用场景**：领养双方在正式完成归属交接前，选择开启可选的“独占试养期”（`matching → trial`）。
- **核心条款要点**：
  1. **独占试养与候补保护**：同一宠物在同一时间段内仅能进入一段有效独占试养，试养期间其他意向申请人自动转为候补队列（`waitlisted`），送养方不得在试养未结束前将该宠物同时交付多人或转为商业出售。
  2. **试养期限与日常照护责任**：双方在快照中明确试养起止日期（建议 7–14 天）及紧急联系人。试养期间宠物归属尚未最终转移，试养人承担日常安全看护、合理饮食与防走失义务；如遇突发疾病，应立即通知送养方并就近送医留存凭据。
  3. **退出机制与双确认安全接回**：试养期内任一方认为不适合继续领养的，可在端内发起“试养退出 / 申请接回”。状态须依次经过：`试养退出发起 → 双方确认接回时间与地点 → 宠物安全交还双确认（或人工争议介入核实）`。
  4. **状态真实性锁定**：仅发送“请把猫接走”消息不代表试养责任已解除；只有双方在端内确认已完成实物接回（或平台凭有效交接证据人工闭环）后，原试养记录方才安全关闭，宠物档案在重新核对当前健康与状态后方可恢复公开可用。

### 2.3 《M&D 宠物出售与有偿转让信息及预约服务协议（草案 v1.0）》

- **适用场景**：个人有偿转让者或合规商家/猫舍与意向买家确认看宠预约（`appointment_proposed → confirmed`）及线下交接登记。
- **核心条款要点**：
  1. **四方主体与价格透明锁定**：卖方确认预约快照中的发布主体、当前照护方、现场接待方、预计收款方及代理关系真实有效；快照锁定的“单宠价格 + 全部必付项 = 预计总价”即为到场看宠基准，卖方不得在买家到场后临时强制加收未披露的疫苗费、芯片费、血统证费、笼具费或强迫搭售商品。
  2. **变更双轨保护（`SC-AP`）**：预约确认后，任何时间、地点、接待人、具体宠物或费用的普通协商变更均生成独立的 `pendingProposal`，买家明确点击“接受”前原有效安排（`effectiveVersion`）不变；买家拒绝新提案不构成违约或失约。若发生原场所不可用、宠物突发健康风险或主体失实等安全事件，系统进入 `safety_hold`（暂停按原安排出发），须重新核对并双方确认后方可恢复。
  3. **活体法律属性与法定质量瑕疵责任**：
     - **7 日无理由退货边界说明**：依据《消费者权益保护法》第二十五条及鲜活易腐/活体交易相关实务规则，活体伴侣动物不属于适用普通商品“7 日无理由退货”的标准标品；但**不适用无理由退货绝不免除卖方的法定质量瑕疵担保责任与检疫合规义务**。
     - **传染病与重大健康瑕疵责任**：卖方交付的宠物必须符合法定动物检疫要求及双方快照确认的健康声明。若交接后在约定观察期（如猫瘟、犬瘟热、犬细小病毒等急性烈性传染病常见潜伏观察期，具体天数与处理方式以双方在快照中锁定的售后条款及当地法规为准）内经正规动物诊疗机构确诊，或被证实卖方存在故意隐瞒已知重大疾病、调包宠物、伪造免疫/检疫证明等欺诈行为，买家有权依法并在平台提交凭据主张解除合同、退还费用或依法索赔。
  4. **平台角色与反私下规避提示**：平台提供主体核验、关系披露、不可篡改预约快照与到访分项反馈存证，不代收货款。提醒买家切勿在未见到真实宠物、未核对快照特征前向私人账户转账大额定金；如卖方诱导脱离平台私下更改看宠地点，买家可随时在端内取消并上传截图举报。

### 2.4 《M&D 代理发布、受托照护与员工接待授权声明（草案 v1.0）》

- **适用场景**：门店员工、受托照护家庭、助宣志愿者或合规代售代理在发布向导或角色工作台绑定单宠/主体授权（`FR-002`、`FR-028`、`FR-037`）。
- **核心条款要点**：
  1. **逐宠逐事项精准授权**：授权分为“介绍协作者（仅限图文宣传与资料整理）”“照护协作者（日常喂养与经披露的协助接待）”与“商业员工/代售代理（在授权范围内报价、接待看宠）”。授权必须绑定具体主账号/经营主体、具体宠物档案及有效期限，不得使用空白全权委托掩盖真实货源。
  2. **连带披露与禁止转委托**：代理方或员工在会话与预约中必须向消费者明示其代理身份、背后委托主体及是否存在独立代理服务费；未经主所有人与平台二次核验，代理方不得私自将接待或宠物交接转委托给第三方陌生门店。
  3. **即时撤权与历史留痕**：委托主体可随时在端内撤销协作者或代理权限，撤权后被撤权账号立即失去对该宠物的新编辑与新预约确认权限，但撤权前已生成的预约快照与沟通记录依法留存备查，委托主体不得以“系员工/代理个人行为”逃避已确认快照中的主体责任。

### 3.2 未成年人保护与监护人授权年度合规审计清单（`LC02` / `SC-AGE`）

1. **前置门禁技术核查（每次发版必检）**：
   - 验证 `requireInteractionContract()` 服务端强校验：未完成手机号验证或年龄未知的账号，调用发帖、评论、私信、加好友、入群、领养申请、预约看宠接口必须返回受控阻断码。
   - 验证未满 14 周岁账号（`under_14_pending_guardian` / `under_14_authorized`）：未获监护人同意前完全禁止互动；获监护人同意后仍强制关闭商业售宠发布、线下签约确认、陌生人私信免审与精确位置共享。
2. **监护人授权真实性抽检（每季度执行）**：
   - 核查监护人绑定流程的验证日志、撤回授权通道可用性（监护人一键撤回后，子账号立即退回只读浏览态并清理非必要互动草稿）。
3. **专门规则与年度合规审计（每年至少 1 次，由产品 + 法务 + 安全联合签署）**：
   - 依据《未成年人保护法》《未成年人网络保护条例》及《儿童个人信息网络保护规定》，审计儿童个人信息存储隔离情况、最小必要字段清单、第三方 SDK 权限调用及删除/注销响应时效，留存书面审计报告备查。

### 3.3 正式公开发布前的外部主体与资质填报核对单（`LC01` / `LC10`）

在将试点环境切换为面向公众开放的生产环境前，必须由运营主体与外部顾问逐项填入真实证照并替换占位符（**当前状态：全部保持待填占位，未作虚假硬编码**）：

- [ ] **运营主体工商信息**：填入真实公司全称、注册地址、常用办公地址及统一社会信用代码。
- [ ] **电信与公安备案**：填入真实 ICP 备案号（或增值电信业务经营许可证编号）、公安机关联网备案号，并在 Web 页脚与端内“关于与规则中心”挂接官方查询链接。
- [ ] **专项举报与未成年人专线**：配置真实有效的违法和不良信息举报电话/邮箱、未成年人网络保护专用投诉通道及知识产权权利人通知接收邮箱。
- [ ] **算法与推荐机制公示**：如后续引入个性化排序，按《互联网信息服务算法推荐管理规定》完成备案并在端内提供一键关闭个性化推荐开关（当前 MVP 采用城市 + 时间/筛选透明排序，不启用黑盒成瘾算法）。
- [ ] **隐私与数据出境核查**：确认对象存储、短信/邮件网关、推送与三方登录（微信/QQ/Apple）全部部署于中国境内合规节点，更新生产级第三方 SDK 目录清单。
