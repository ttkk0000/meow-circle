# M&D 冷启动、走失互助与登录规则增补

日期：2026-10-16｜状态：武汉／上海首发已由用户确认；来源与运营方案待评审｜尚未实施

依据：用户提出初期内容不足，可引入宠物走失信息、点击地图查看，并优化登录与规则。本稿补充 [PRD 2.0](../bmad/prd.md)、[UX 2.0](../bmad/ux-design.md)与 [Figma 学习稿](MND_FIGMA_STUDY_BRIEF.md)，不声称这些功能已经上线。

[打开四条流程图](flows/cold-start-and-auth.html)：来源入库、地图与线索、登录与恢复、领养核验与举报。真实性与举报有效性另见[共用信任规范第 12–16 节](MND_TRUST_AND_DISCLOSURE_SPEC.md)。

2026-10-19手机增补：用户明确微信、QQ快捷登录，iPhone另有Apple登录；[认证完整规划](MND_MOBILE_AUTH_PLAN.md)与[手机覆盖复核](figma-study/audits/2026-10-19-mobile-docs/MOBILE_DOC_COVERAGE_AUDIT.md)为本轮入口。多宠／圈子／走失等已有原生设计，但关键结果、权限与账号链仍有缺项，不按屏数宣称全量完成。

## 1. 推荐结论与取舍

建议以“同城真实互助”解决冷启动：自有编辑内容作稳定底座，授权合作补充真实领养与走失信息，自动采集只作获准来源的辅助管道。不要为填满页面假造用户、领养名额、求助、评论或定位。

| 方式 | 优点 | 代价／边界 | 本轮建议 |
|---|---|---|---|
| 自有内容＋合作方投稿 | 能控制来源、更新时间和回复责任 | 需要运营建立供给 | 首发主方案 |
| 获准 API／开放许可／白名单采集 | 有助扩大覆盖并同步状态 | 需逐源核对许可、字段、频率与撤回机制 | 合作后逐步接入 |
| 全网大量搬运 | 表面上内容很快变多 | 过期、重复、隐私、版权与来源限制难控 | 不作为默认方案 |

用户已确认首发武汉与上海。两城分别建立来源、审核、状态维护与内容供给，不共享“附近”排序池；猫咪默认筛选，狗狗及其他允许物种同层可达。该选择来自本轮用户回复，不由旧学习稿上海示例推断。不承诺找回率、全天响应或“平台已验证全部真实性”。

首次明确选择武汉／上海，记住上次城市并允许切换；不以 IP 或 GPS 静默替换用户选择。可提供“其他城市登记意向／看公开指南”，但不暗示已开通当地实时服务。城市、行政区、时间和物种筛选在列表／地图间共享；可选“查看另一城”，须显示正在切城。

武汉和上海独立核对上线条件：可持续来源、明确审核与撤回负责人、真实维护时段、地图服务可用及隐私投诉路径。某城未具备条件时标“准备中”，不因另一城已开通就展示同等服务承诺。两城均从少量可维护区域起步，具体城区依据伙伴与实际供给决定，不凭城市名编造案例覆盖。

## 2. 首页与内容填充

现行五主入口为“社区／领养／发布／消息／我的”。社区提供“同城互助”入口，内含走失、拾获、目击线索与列表／地图切换；发布是动作入口。旧学习稿“找宠Tab”仅为历史。商业信息持续标注“出售与有偿转让”，不能与“走失互助”混为一个搜索结果池。

首屏先展示所选城市、可用的真实内容、互助入口与少量指南；不以密集红色警报铺满首页。提供“只看日常／减少走失内容”选择，不用算法把所有用户永久带入焦虑内容。

建议首发准备约 12–20 篇自有内容，属于运营试点目标而非上线硬门槛：新手照护、室内防逃、走失后的信息记录、狗狗日常、其他物种照护入门等。健康内容标明来源与审阅范围，不替代兽医诊疗。合作信息按实际授权量展示，宁可少，不编造数量。

| 内容类型 | 展示身份 | 默认分发与空态 |
|---|---|---|
| 自有编辑／邀约内容 | M&D 编辑部或真实授权作者 | 可跨城市阅读，不伪装附近动态 |
| 合作领养／走失个案 | 具体组织或原作者；授权转载单独标记 | 按城市、更新时间、物种筛选 |
| 外部线索 | 原来源、原文时间、最近检查、当前核对状态 | 独立来源标记，不计为活跃本地用户 |
| 演示数据 | 仅开发／设计环境明显标记 | 生产种子不导入；不得推送或出现在真实地图 |

本地为空时，明确“这里暂时没有符合条件的有效信息”，提供扩大区域、查看更早记录、发布真实求助、阅读指南。不能自动替换为外地案例却继续写“附近”，不能把抓取失败或离线缓存当作零案例。

## 3. 来源与自动采集边界

### 3.1 优先次序

第一优先：宠物主人／拾获人本人发布；第二优先：救助组织、宠物医院、社区等明确获准的协作供给；第三优先：经逐源审查可用的公开 API、开放许可或书面授权页面。公开可见、允许机器人访问、允许转载、允许复制照片与允许公开联系方式是不同事项。

公开个人信息并非可无限再利用。个人信息保护法第 27 条限制已公开信息处理范围，第 28–29 条对敏感信息提出更高要求；涉及人身行踪等风险需具体评估。本稿建议默认最小化、脱敏和撤回，不构成对任一网站采集合法性的结论。[法律依据](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_f374e8245320413181742e6d1baf4366.html)

### 3.2 发布前必经流程

来源许可与服务条款审查 → 白名单接入 → 最小字段提取 → 去重候选 → 地点和时效核对 → 人工审核 → 脱敏发布 → 持续状态更新／撤回。

- 本轮不启动爬虫、不采集真实个案、不联系原作者；指定来源及其可使用范围后才做实际接入。
- 不进入私密群、需要他人登录授权的空间；不绕过验证码、反爬、访问控制或限流。
- 无可确认利用依据的来源先不入库；仅放原文链接也不自动等于合规。
- 照片、原文和摘要分别记录许可。无照片权利时不复制，不用相似生成图冒充该宠物。
- 默认不复制电话、微信号、人脸、门牌、聊天截图和完整家庭地址；海报及照片里的隐私同样要检查，不能只遮文字字段。
- 原文相同用来源 ID／规范 URL 幂等导入；图片相似、相近时间地点只提示可能重复，不自动断言同一宠物、合并当事人或覆盖状态。
- AI 只提取候选字段，不补猜走失时间、物种、性别、地点、归属或“已找回”。所有人工纠正保留依据。
- 原文删除／作者拒绝／授权撤回进入即时隐藏与复核队列，清理公开列表、地图、搜索、缓存及自有分享预览；已外发截图无法保证召回，需在发布前告知。

### 3.3 四条独立状态轴

| 维度 | 示例状态 | 不能互相推导 |
|---|---|---|
| 来源权利 | 待核对／可使用／撤回／不可使用 | “网上公开”不直接变成可使用 |
| 审核 | 待审／需补充／通过／隐藏／争议复核 | 审核通过不等于确认主人身份 |
| 事件 | 仍在寻找／可能匹配／已找回／已结束／状态待更新 | 时间到期或原文消失不等于已找回 |
| 时效 | 原发布时刻／最近联系确认／最近抓取检查 | 抓取检查成功不能刷新原事件活跃时间 |

## 4. 地图交互：标的是事件，不是实时宠物

列表卡片展示物种、走失／拾获、事件时间、区域、来源类型、最后确认与状态。点击位置摘要打开同一案例的地图选中卡；从地图返回保留原筛选、位置和滚动进度。卡片主点击仍进案例详情，不把所有点击都送往外部地图。

地图只标“走失地点”“目击地点”“拾获地点”，并标明各自时间、精度和来源；不画推断移动轨迹，不把多条未经核实目击连成宠物真实路线。用文字与图形区分类别，不能只靠颜色。

### 4.1 地点可展示条件

| 获得的信息 | 地图行为 |
|---|---|
| 原作者确认的公共场所与地点 | 按已选公开精度展示；显示事件发生时间，不称实时位置 |
| 小区／居所附近 | 默认区域级或固定聚合区域展示，不公开楼栋／门牌；不额外精确化 |
| 仅有城市／行政区 | 区域范围或列表，明确“仅到区级”；禁止以区中心伪装准确点 |
| 文本重名、无时间或定位存疑 | 保留原区域说明并提示待核对；不生成精准针点和路线 |

公开点与审核用原始点分开存储；面向游客、登录用户、推送、分享和外部地图都只返回公开精度。不能只在 UI 遮住精确坐标、接口却照常返回；不对同一私人地点重复随机抖动，以免平均多次查询还原。

“查看地图”与“定位我”是两件事：展示事件点不要求获取用户 GPS。首次默认手动选城市；点击“定位我／距离排序”时解释用途再申请前台权限，允许仅粗略位置；拒绝后仍可选城和看列表。不启动后台持续定位。

首阶段可采用列表＋“在地图查看”外跳，成本较低；第二阶段再做内置多点聚合、筛选和底部详情卡。高德 URI API 支持已知经纬度的标注与移动端调起；记录坐标系，正确处理顺序和转换，不能混用 GCJ-02、WGS84、BD-09。[官方说明](https://developer.amap.com/api/uri-api/gettingstarted)

外跳前说明“将在第三方地图打开此事件的大致位置”；只传公开地点与中性标签，不把个人电话、宠物主姓名、私密线索或内部 ID 拼进 URL。未安装／不可用时回退到网页或文字地址；无确认点时不提供误导性导航，也不推荐擅入私人场所。

地图 SDK 的初始化与定位调用按所选产品当前隐私方案执行，取得相应有效授权前不触发收集型初始化；用户拒绝时保留不依赖该 SDK 的文字列表。[高德合规方案](https://lbs.amap.com/api/compliance-center/check-and-reference/sdkhgsy)

## 5. 求助、目击与认领

本人发布最少需要：走失／拾获性质、物种、可辨认描述、事件时间（允许约略或未知）、区域、发布者与宠物关系、站内可联系账号及公开精度预览。图片允许后补；没有准确坐标不阻止合理的文字求助。

“我看到疑似宠物”生成独立私密线索，包含目击时间、地点精度、描述及可选图片，只向案例维护者和获授权审核人员开放。不因某人发一条评论就改掉主案例位置、公开他的行踪或通知全城。

拾获者可保留一项不公开的特征，用于向认领者核对；历史照片、既有照护材料等通过私密渠道必要提交。控制手机号只说明账号联系渠道，不证明宠物归属。外部作者认领转载记录也必须单独核对，不由昵称／头像相同自动交出编辑权限。

匹配只是候选，不公开认定所有权。交接建议在安全公共场所进行；归属争议交给人工处理或适当机构，平台不自动裁定。禁止以“提供线索前先付款”、二维码、索要验证码等方式套钱；首发不代收悬赏、不承诺赔偿、不做收费置顶求助。救急内容不夹带未标注商业导流。

建议时效试点参数：本人案例 72 小时提醒更新；外部记录连续 7 天未获来源／当事人状态确认时转“状态待更新”、退出默认近期地图与主动提醒，但不标成“已找回”。仍可查看更早记录；作者更新后进入必要复核，不自动频繁推送。具体阈值可按运营能力调整，并非法律期限。

## 6. 登录：有价值之后再要求身份

2026-10-20 用户更新：普通登录支持同一账号的唯一账号名／邮箱／手机号＋密码、邮箱验证码，以及已绑定微信／QQ／iPhone Apple；不强制手机短信。首次发帖、评论、私信／群聊及对外申请等动作前须验证当前手机号，验证后不逐条重复发短信；更换手机号需重新核验且保留原账号。细则以[M&D手机认证规划第0节](MND_MOBILE_AUTH_PLAN.md)为准，邮箱与新权限关卡尚待实施。新用户不必同时填写三个登录标识、头像和宠物档案。

提供信息发布、即时通讯等服务需满足适用真实身份认证要求；不是要求所有游客一进首页就交身份证。具体认证和未成年人处理方案需上线合规评审。[现行管理规定第 6、12、13 条](https://www.cac.gov.cn/2022-06/14/c_1656821626455324.htm)

| 触发动作 | 访问要求 | 返回与恢复 |
|---|---|---|
| 浏览、筛选、案例详情、公开位置、来源链接 | 游客可用；地图产品按必要授权独立处理 | 不强制登录、不先要 GPS |
| 发布、评论／回复、私信／群聊、提交私密目击、申请领养、确认预约 | 登录且当前手机号已验证，另检查原有业务权限；已验证后不重复短信 | 登录／手机验证后恢复原案例与草稿，不自动发送 |
| 跨设备收藏、订阅区域提醒 | 登录；通知许可另行询问 | 只完成用户本次选定动作，不顺带营销订阅 |
| 举报违规、隐私投诉、撤回转载请求 | 保留不强制注册的安全入口 | 可用工单号／安全回执；必要回访信息单独说明用途 |
| 查看／修改账号、绑定换号、导出注销 | 登录；高风险动作再验证 | 换号不自动新建账号；失败可恢复／申诉 |

### 6.1 页面与验证状态

- 普通登录页提供账号名／邮箱／手机号标识和邮箱验证码方式，保留“先逛逛”和清晰返回；手机验证页有号码区号及支持系统填充／粘贴的验证码框。标签不能只靠占位文字。
- 发送前说明邮箱注册／登录、交流前手机验证或换号的具体用途，手机验证不自动另建账号；服务协议／隐私告知由用户明确选择，不能预勾或与营销、公开位置、通知权限合并。
- 验证码阶段支持号码修改、可读的重发倒计时、失败原因与恢复；服务端限流为准，前端倒计时不能充当防刷。错误不通过颜色单独表达，不向读屏每秒广播倒计时。
- 生产需真实短信通道、一次性且分用途的验证码、有效期、尝试上限、频率与费用风控；开发固定码和日志码不能在生产使用。认证成功也不授予“真实宠物主人”徽章。
- 短信没到／无网络／第三方取消／账号受限／会话过期分别解释；重试保留必要输入，草稿仅存受控范围，验证码不进入草稿或分析日志。
- 登录成功后恢复 `return_to` 对应的站内页面和动作意图；限制为允许的站内目标，避免开放重定向。不将用户带回首页要求重来，不自动发布、私信或提交申请。
- 微信等多个身份绑定需明确确认与再验证，不能因邮箱／头像相同自动合并。退出清理身份私密缓存，公共阅读可继续。
- 位置、相册／相机和推送在需要时分别申请；优先系统照片选择器，不为了发一张宠物图索取全相册与通讯录。

## 8. 字段与后台能力边界

最小记录分成：来源记录、事件案例、单条目击、关系／编辑权限、状态历史、审核记录。不要把一条抓取动态直接变成平台原生主人账号。

来源记录包含规范 URL、来源主体、使用依据与范围、原发布时刻、最近抓取检查、最近状态确认、撤回状态；事件保留公开位置与私密位置的独立权限、坐标系、定位方法、精度／置信范围及人工修正依据。

后台必须有来源暂停、重复候选、脱敏审核、作者认领、状态过期、隐私撤回与申诉队列。导入任务需可幂等重试、限频、记录失败，不因采集失败清空已有记录；只允许已审查域名和公开目标，防止 URL 导入访问内部网络。

数据保留期、访问角色、日志脱敏、删除与备份清理需分别定义。求助结束后默认退出活跃地图与提醒，关闭公开联系方式；公开“找回故事”需另行授权，不能把精确位置与证据永久留作运营素材。

## 9. 优先级与可验收条件

这里的 P0／P1 是本增补建议，不改写 PRD 中已经定义的需求编号。

| 编号 | 优先级 | 可验收结果 |
|---|---|---|
| CS-01 来源透明 | P0 | 每条外部卡可见来源、原时间与核对状态；无许可记录不能发布；抓取不能刷新事件时间 |
| CS-02 真实空态 | P0 | 区分零结果、离线、加载失败、过期缓存；无演示数据混入真实列表／地图 |
| LF-01 地图位置 | P0 | 点卡对应同一事件；位置类型与时间可见；区级／存疑地点无伪精准针点；拒绝 GPS 仍可浏览 |
| LF-02 私密线索 | P0 | 目击时间与主事件分离；无权账号不能读取原始坐标或材料；提交不自动改事件位置 |
| LF-03 状态闭环 | P0 | 找回、结束、待更新分开；旧案例不误推；撤回同步清理自有公开索引及缓存 |
| AU-01 渐进登录 | P0 | 游客可读；动作触发认证；成功回原页且保留草稿；取消不丢公共阅读位置 |
| AU-02 生产认证 | P0 | 真实短信、限流、一次性验证码、协议记录与高风险再验证就绪后才能上线相关交互 |
| GOV-01 安全运营 | P0 | 无账号隐私投诉／撤回入口可达；用户看到真实服务时段、受理状态与申诉路径 |
| LF-04 内置地图 | P1 | 地图／列表同一筛选；聚合不重复计数；加载失败回列表；地图非唯一信息载体 |
| CS-03 合作同步 | P1 | 每源白名单与撤回机制完整；重复项不制造新求助；暂停来源不破坏历史与申诉记录 |
| NT-01 区域提醒 | P1 | 用户主动选区域、物种和频率；可静音退出；去重、冷却；无自动全城急推 |

首发不做：大规模全网搬运、活体轨迹推断、平台自动裁定归属、收费求助优先曝光、悬赏代收、虚假评论和虚构求助。提醒推送是产品提案，不在本轮创建任何自动化。
