# 全流程跨端布局与状态契约

本文件与 `cross-platform-full-state.json` 的精确节点映射配套。只说明设计和后续实施规则，不表示客户端代码已经完成。

## 布局

| 可用窗口 | 设计行为 |
|---|---|
| Web 宽屏，参考 1440×1000 | 顶部全局导航、左侧模块入口，正文居中，内容最大 820；页面滚动与任务操作区分开 |
| Desktop，参考 1440×1000 | 原生窗口标题区、常驻主导航、模块上下文和正文工作区；点击、键盘焦点与触控均可到达完整功能 |
| 平板横屏，参考 1194×834 | 80 宽图标主导航、模块侧栏、独立正文；短高窗口允许正文滚动，输入／确认操作保留可达 |
| 平板竖屏，参考 834×1194 | 收起次要模块侧栏，保留主导航和当前任务；正文扩展，表单与评论自然换行 |
| 平板窄分屏，744 宽及以下 | 复用竖屏结构；可用正文不足 600 时收起主导航到菜单，表单保持单列；图片流按手机紧凑卡片最小宽 160 决定是否保留双列 |
| Web 窄窗，约 390 宽 | 复用手机内容层；顶栏收成品牌与当前模块，主导航改底部或菜单；侧栏转抽屉，任务正文不横向滚动；社区图片流延续手机紧凑双列，长详情与表单单列 |

判断依据是当前窗口可用宽高，不是设备型号或仅判断横竖屏。平板不锁定方向。约 1100 宽以上再展开模块侧栏；中间窗口参考竖屏结构。Desktop／Web 窗口缩小后也逐层收起模块侧栏和主导航，不能保持宽屏栏数压窄正文。Android／iPadOS 分别实现布局；共享同一逻辑状态和权限语义。

图中尺寸为逻辑窗口参考。各端另行测量系统状态栏、手势安全区与键盘 Insets；Desktop 顶部是窗口装饰示意，实施时使用平台窗口能力，避免重复绘制标题栏。核心导航保持社区／领养／发布／消息／我的；宽屏另保留互助入口，窄窗由相关上下文进入互助。

## 内容、输入与旋转

- 每个四向对应稿使用同一 `mobileKey`；旋转只改变布局，保留当前宠物、会话、受众、筛选、滚动锚点和草稿。关闭输入面板也保留草稿。
- 表情面板在大屏可使用固定宽度浮层；不把 128 个表情横向拉伸。贴纸预览与发送分开，外接键盘不显示虚构软键盘。
- 长文本按固定可用宽度换行；照片独立裁切，图标和表情保持比例。原稿里的错误、空态、选中、失效、角色限制都保留独立状态。
- 短高窗口优先保证标题、返回和当前操作可达；正文／较长选择面板分别滚动。软件键盘出现时扣除真实键盘和系统安全区。
- 切换方向、窗口、输入设备不重复发送，不自动确认、不重新创建草稿，不覆盖其他设备版本。冲突保持显式处理。

## Figma平板预览控制（2026-10-22）

[平板预览优化](PAD_PREVIEW_2026_10_22.md)为704组横竖屏稿增加右上角“预览 · 横屏／竖屏”，并将View prototypes入口精简为两个方向。图层名为`Prototype only / Orientation switch`，仅供Figma演示，**客户端不实现该按钮**。Figma以同状态原稿间手动Navigate切换；带Responsive的链接仅控制播放端重排，不能视为自动旋转、真实断点切换或输入／滚动保留的运行证据。真实产品继续按本文可用窗口与上下文保留规则实施。

## 权限与导航

- 申请、私密线索、认领材料、核实资料、朋友圈受众、群主转让及账号注销均保留手机稿中的权限和主动确认条件。
- 预约当前版本、提案、历史版本分开；恢复旧时间产生新提案并重新双方确认，不能直接恢复为生效。
- 新稿同模块内使用 Figma 页面内跳转；跨模块使用精确 Figma 节点链接。它们服务设计评审，不能视为真实服务端调用或完整客户端路由实现。
- 返回优先恢复原任务上下文；独立深链无可用前序时返回所属模块。系统返回、Esc、关闭浮层不触发提交。
- 触控目标至少 48；Web／Desktop 需有清晰焦点、可按 Tab 到达的主操作，Esc 关闭临时层。悬停只能增强提示，不能承载唯一入口。

## 主题与实施边界

当前只使用手机 V2 默认浅色模式 `56:0`。原 Honey／Mint／Night／Neutral 仅作历史参考和未来 token 扩展；本轮不放主题切换入口，不随系统进入深色。

结构回读与 Figma 截图检查属于设计验证；真实浏览器、Android 平板、iPad 横竖屏、分屏、键盘和屏幕阅读器仍须在客户端实施后，取得运行授权再验收。
