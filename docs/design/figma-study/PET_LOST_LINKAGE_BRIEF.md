## 1. 核心决定

用户可以从自己的宠物主页标记走失。**修改宠物状态、发布求助、分享给朋友、接收附近提醒，是四项不同授权**。不会因为改了状态，就公开档案、推送全城或向所有群发送消息。

本版以“先保存本人确认的走失状态，再选择是否发布”为推荐流程；主人与授权照护人员的具体权限、提醒定位模式仍待评审。仅制作评审材料，不修改真实用户数据或权限。

四屏 PNG 是内置 image_gen 生成的位图提案，展示自己的宠物、求助填写、私密线索、确认找回；不涵盖全部状态，不是可编辑 Figma UI 或可交互客户端。照片和资料均为示例，不是真实走失案例。

## 2. 四种状态不要混在一起

| 对象 | 状态／用途 | 不代表什么 |
|---|---|---|
| 宠物档案 | 在家／走失；“在家”指主人已确认恢复照护，不是 GPS 位置 | 不改变所有权、领养性质或医疗结论 |
| 本次求助事件 | 草稿／待审核／寻找中／暂停展示／已找回／其他原因结束 | 结束不等于找回；暂停不等于删除历史 |
| 每条目击线索 | 待查看／待核实／有帮助／不匹配／举报处理中 | “相似”不代表识别成功，也不自动更改宠物状态 |
| 内容发布与核验 | 授权来源、审核结果、主人确认、更新时间分别说明 | 电话核对、照片上传不等于归属或健康认证 |

“走失”只描述找不到宠物这一事件，不与“待领养、已领养、在治病”等属性互相覆盖。视觉状态同时用文字与图形表达，不只靠红绿颜色。

同一只宠物原则上只有一个活跃求助事件；反复点击进入已有事件，不制造重复推送。草稿、暂停、结案历史保留各自含义。再次走失建立新事件并关联原宠物，重新填写本次时间和地点，不复活旧求助。

## 3. 主人主线

1. 我的 → 选择宠物 → 宠物主页 → 标记走失。
2. 确认层说明影响，提供“仅修改状态”“标记走失并继续求助”和取消。确认前不更改任何状态。
3. 确认后，本人档案显示走失及“继续完善求助”。未公开求助时，仅按原档案权限显示；私密档案仍私密。公开档案是否展示走失标签也由本人明确选择，不因这一步自动改变。
4. 创建本次求助草稿，预填宠物名、物种、已选照片与已记录特征；最后见到的时间、地点由用户填写，不使用当前 GPS 猜测，不把 EXIF 当事实。
5. 预览将对外出现的全部内容和粗略地点。选择是否进入互助列表／地图；朋友和群分享另外选择。没有公开同意时只可存草稿，不能显示发布成功。
6. 提交成功后先显示真实审核状态；尚未通过可展示规则时，不向他人分发。失败保留草稿，重复请求不能重复建案。
7. 寻找中进入维护页，处理线索、补图、更新动态、管理公开范围，必要时暂停展示或结束。
8. 主人确认接回 → 阅读收尾影响 → 确认找回并结束求助 → 宠物恢复在家，本次事件已找回。

放弃公开草稿，不撤销此前明确确认的私人走失状态；返回宠物主页时告知“状态已保留，求助尚未发布”。如果第一步尚未确认，取消不产生变化。误标且没有公开事件，可确认恢复在家；已有公开事件时走“标记有误／结束求助”路径，不能伪装成成功找回。

## 4. 求助填写与公开范围

必需信息：所选宠物、最后见到时间或明确的估计时段、公开区域、可供辨识的照片或描述、发布者确认与站内联系入口。具体物种字段继承宠物资料，猫、狗及其他宠物分别补充适用特征；未知可以标记未知，不诱导编造。

照片可以来自既有宠物资料，也可补充近期照片；保留来源／拍摄时间说明，不给“真图保证”徽章。首版只有图片和文字，照片上传限额与压缩阈值在实施评审确定，不把视觉网格当产品上限。

| 信息 | 公开读者 | 主人／授权处理人员 |
|---|---|---|
| 宠物名、选中的识别照片与特征 | 经发布者逐项确认的本次快照 | 完整本次求助资料 |
| 最后见到时间 | 标示确定／估计，不展示成实时在线 | 可修改并保留更正记录 |
| 地点 | 用户确认的粗略区域／模糊范围；有不确定说明 | 用户主动提供的详细位置，受控访问 |
| 目击照片、地点和联系信息 | 不自动出现在公共详情或评论 | 仅该线索授权范围内可见 |
| 私密宠物日记、家庭地址、证件 | 不公开，也不在通知或分享缩略图中泄露 | 不因找宠而自动授予全档案读取权限 |

公共地图标识是“这次事件最后见到的区域及时间”，不是宠物实时位置。目击点不自动移动主标记或串成逃跑轨迹。没有可靠坐标时展示区域说明，不伪造精确图钉。

浏览互助列表、查看已发布区域和手动选择城市，不强制申请 GPS。填写地点也允许手动输入和选择。定位只在用户主动使用对应能力时解释用途并申请；未授予精确位置仍可使用其他能力。首发武汉和上海，其他城市不虚构案例或覆盖承诺。

## 5. 发布后如何串联

所有入口引用同一个本次 case ID，不复制成互不更新的“走失帖子”。

| 表面 | 何时出现／更新 | 关键保护 |
|---|---|---|
| 自己的宠物主页 | 保存状态后，显示维护入口与事件摘要 | 不公开全部日记；私密资料入口不外泄 |
| 互助列表与地图 | 用户同意公开且满足发布条件后 | 显示最后更新时间和粗略区域，不等于实时追踪 |
| 宠友圈 | 用户主动分享，仍遵守所选朋友受众 | 摘要仅包含经确认的求助快照；卡片不能扩大原内容权限 |
| 群聊／私信 | 用户选定会话并确认发送 | 不自动建群、不群发、不把群成员全部加入订阅 |
| 5–100 公里提醒 | 接收者主动订阅并满足地点／物种／频率等条件 | 默认关闭；系统通知授权与应用内订阅分别控制 |
| 通知与历史分享卡 | 读取同一个事件的最新可读状态 | 结案后显示已找回／已结束，不继续传播旧“寻找中”状态 |

宠友圈的日常流不因关注了宠物就自动订阅其全部警报；主人可以主动分享求助卡，读者可自愿“关注本次进展”。个人私聊、群聊和圈子互不替代。

有进行中的领养申请／到访时，建议暂停该宠物的新预约和交接，向已受影响的参与者说明“该宠物暂无法预约，等待主人更新”，避免暴露失联地点。不暂停整个账号或无关宠物；恢复需主人确认并按原流程重新安排，不自动恢复旧约定。本条为待评审建议，不代表现有代码行为。

## 6. 附近提醒：接收端单独设置

沿用用户提出的 **5–100 公里可调、可关闭**。推荐首版使用“用户选择的提醒中心／最近一次主动授权位置”，允许手动换中心或主动刷新；不默认后台持续追踪。是否使用动态跟随仍待用户确认。

设置说明中心位置、半径、物种、提醒方式／频率；距离按提醒中心与事件位置及不确定范围判断，不冒充人与宠物的实时距离。范围不确定时说明“可能位于你的关注范围”，不提供虚假的精确公里数。

推送条件须同时满足：事件允许公开且寻找中、订阅有效、位置和物种匹配、未关闭／拉黑相关提醒、通知渠道可用、去重和冷却规则通过。发布成功不保证所有人收到。拒绝系统通知仍可在应用互助页查看；关闭 GPS 不自动开后台定位，也不应清除手动订阅中心。

同一事件的新照片、普通评论、重复线索不逐条广播。重要更正可以进入进展摘要，是否再次推送需频控和用户选择。变更半径不重发全部历史案例；找回／结束后先停止排队中的活跃警报，发送前再次校验事件状态。

## 7. 线索、评论和联系

“我可能见过它”打开独立线索表单：看到时间、地点、可选照片、辨识描述、站内联系选项。提交前明确“仅主人及获授权人员可查看”。不公开家庭地址或要求发布手机号，不要求先缴费才给线索。

普通留言可以是鼓励与讨论；只有明确提交的内容才进入线索队列。主人可引导留言者补交线索，但不能无同意把其私信或评论转换为公开目击事实。

收到回执只表示提交成功；“待核实”不能显示“已定位”“匹配成功”。举报数量、点赞数不证明真假。主人可把线索标为有帮助／不匹配，补充处理备注；不能改写对方原话。恶意骚扰、索费、盗图等交由独立举报和复核流程，受理不等于判定违规。

站内联系沿用消息请求、拉黑、举报规则；不为“紧急找宠”绕开陌生人接收设置。线索通知不附带精确地点／原图／私密电话号码。事件结束后是否保留站内聊天遵守会话规则，不等于所有私人对话被自动删除。

## 8. 找回与其他结束

“我已找到”先进入确认页，不即点即改。初始确认项未勾选，主要按钮不可提交；示例四屏可展示已勾选后的可提交状态。主人确认“是本宠物并已接回”，可补充时间和记录；不强迫公开照片，也不把第三方一句“找到了”当主人确认。

收尾顺序作为一个可恢复操作：先锁定本次事件的关闭意图并停止新增警报，再将事件标为已找回、宠物恢复在家，更新公共入口和分享卡，最后返回可见的处理结果。部分同步失败时显示“结束处理中”，允许安全重试，不能一边显示已找回一边继续警报。具体事务实现待工程评审。

- 互助活跃列表／地图移除寻找中标记；原详情保留最小化已找回状态和时间，不冒充删除了所有记录。
- 宠友圈／群／私信中同 ID 的站内求助卡读取已找回状态；应用内缓存重新校验。无法召回外部截图或历史锁屏通知，应如实说明。
- 私密线索始终受限；结束后公共联系入口关闭，详细地点进一步收紧。授权处理人员的保留时长、审计和删除政策另定，不能用“关闭”承诺立即抹去全部证据。
- 通知“关注本次进展”的用户或参与者时使用最小化状态摘要并遵守其设置；不向全半径人群再次群发喜报。
- “分享团圆日记”为独立可选动作，默认不发布，不自动公开此前私密宠物资料和帮助者身份。
- “其他原因结束”“标记有误”“暂不公开寻找”单独提供，不统称找回。选择其他结束后，宠物可仍保持走失；必要时本人另行确认状态。
- 主人失联、内容长期未更新或管理员隐藏，只能表述“待更新／已隐藏”，不能代主人宣称已找回。沿用基础规范的维护提醒和过期状态。

## 9. 关键异常与权限

| 场景 | 页面与行为 |
|---|---|
| 误选另一只宠物 | 预览显著显示本次宠物；提交前可返回更换，不串接另一只猫的旧事件 |
| 已有寻找中事件 | 展示现有事件与维护入口，不重复建案或重复发通知 |
| 无照片／特征不全 | 可存草稿，说明补充辨识信息的价值；不生成虚假资料 |
| 定位／通知被拒绝 | 提供手动区域与应用内查看，不阻止基本资料和草稿 |
| 提交中／断网／离线 | 禁止重复提交、保留草稿；未知结果先查询原操作结果，不新建副本 |
| 审核待处理／未通过 | 仅主人看到状态及修改／申诉入口，不显示公共推送成功 |
| 资料或地点更正 | 保留更正时间，引用卡更新；新增敏感信息重新预览并确认 |
| 关闭中同步失败 | 显示结束处理中，停止继续广播，允许幂等重试 |
| 朋友关系／受众变化 | 当前访问重新校验；旧分享不赋予私密内容权限 |
| 事件再次发生 | 新事件新时间地点，旧历史只作本人可查引用 |

只有主人能确认接回和结束；建议邀请照护人员可补图、备注和协助核实，不能默认更改所有权或结案。若将来允许代结案，必须单独授权与审计。平台人员可审核、隐藏或复核违规内容，不能悄悄改写主人事实；紧急特殊处置需记录原因与可申诉入口。

## 10. 设计落点与验收

页面清单是 18 个**待创建场景**，不是 18 个已完成原生画板。已有 134 状态中虽有走失列表、地图、详情、发布和维护页，但未读取其当前宠物身份前不得直接用新小满流程链接旧案；也不能把旧原型当作本次新联动的交付。

应验收：多宠物选择、个人状态和公开授权分离、取消草稿不误广播、私密档案不泄露、同宠物单活跃事件、待审核不分发、武汉／上海粗略定位、权限拒绝可继续、私密线索访问、评论与线索分离、提醒去重／关闭竞态、结束处理中、其他结束非找回、新事件不继承旧地点、分享卡更新和外部截图边界。

控件沿用已选 Friendly：主要／次要横向按钮 48 高、24 圆角；图标触控区至少 48；文本与状态清晰命名，焦点轮廓与背景留出间隔；确认、错误和处理中均有文字反馈。320 宽、大字体、键盘、读屏、对比度与真实设备验证仍待原生设计落地后完成，不因这张 PNG 声称通过无障碍验收。
