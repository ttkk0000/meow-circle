## 与真实管理能力的关系

范围依据现有 `web-client/src/operator/OperatorApp.tsx`、`/api/v2/ops`适配和角色合同，不默认授予全用户资料浏览能力。

- `moderator`核实举报、申诉与权利事项；原文、事实、补充及当前版本分别呈现，不由举报直接推断处罚。
- `privacy`按明确事项编号读取资料请求、分类处理及保全；不将部分删除显示为全部完成。
- `identity_verifier`核对可信关系证据，监护人主动同意单列；`authority_verifier`与其它角色互不自动授予。
- 发布准入核对公开主体、文本、联系方式和适用版本；配置由部署方维护，本页没有直接发布协议的设计动作。
- 凭据只驻留当前页面内存，消费者登录、worker或技术运维身份不替代业务角色；访问受限时隐藏私密资料。
- 结果未知先重读原事项及版本，没有独立操作回执时不宣称成功；保留原说明，避免另发副本。

所有写操作在当前设计未连接状态保持禁用。现有 `/app/operator`仍是既有核验实现；后续将本批13稿落地代码时，应在公共外壳／队列／详情／确认结构中组合现有能力，并按各业务实际版本与恢复合同接线。本设计不新增服务端权限或数据访问承诺。
