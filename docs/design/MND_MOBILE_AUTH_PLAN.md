## 0. 最新账号规则（2026-10-20 用户决定）

2026-10-21逻辑复审后的最新稿见[六处修订交接](figma-study/LOGIC_FIX_HANDOFF_2026_10_21.md)：短信发送／核对分用途，成年核验不落普通账号列表；删除／注销分别在范围与本次身份核对后最终提交。服务端资格和真实通道仍待实施，不能把设计变量当认证结果。

2026-10-21用户确认年龄策略：年满14岁可交流，未满14需监护授权，商业发布和线下签约由成年人办理。年龄／监护、当前手机号验证、角色和资源状态分别检查；完整矩阵与撤回／失效／申诉见[安全合同SC-AGE](MND_SAFETY_AND_LIFECYCLE_SPEC.md)。本轮同步Figma与设计合同，B04、年龄及监护服务仍是实施缺口，不得用本地状态假装接通。

### 0.1 同一账号与三个唯一登录标识

- 一个用户账号对应稳定的内部 `user_id`。账号名、已验证邮箱、已验证手机号都指向这个账号；换一种方式登录，资料、宠物、好友、聊天、草稿和权限仍属于原账号。
- 账号名全站唯一；每个已绑定邮箱、手机号只能属于一个账号，一个账号最多各绑定一个当前邮箱和手机号。不要求用户首次进入时同时填写三项；缺少的登录标识可后续绑定。
- 账号名与展示昵称分开：昵称可以重复，不能作为登录标识或账号归属证明。账号名还未由用户设置时可以分配唯一默认值，不强迫用户在首屏填完资料。
- 日常支持“账号名／邮箱／手机号＋密码”和“邮箱＋验证码”，以及已绑定第三方登录。输入手机号作为账号标识不等于必须再收短信；没有设置密码的账号使用已验证邮箱或其他已绑定方式。
- 邮箱必须验证成功后才能成为登录／恢复标识，不能根据输入地址或第三方返回的相同邮箱自动归并账号。任何新增绑定都要验证当前账号及待绑定标识，不能只知道对方邮箱或手机号就接管账号。
- 唯一性在服务端和数据库保障：标识标准化后使用唯一约束，绑定／换绑在同一事务内完成；并发注册或换绑冲突不得覆盖既有账号。未绑定值不参与已绑定唯一约束。
- 账号名去首尾空白并按不区分大小写匹配；邮箱去首尾空白，产品登录键按不区分大小写匹配，不擅自删除点号或 `+` 后缀。手机号按区号和号码统一格式。账号名禁止使用邮箱形式或纯数字，避免与邮箱／手机号登录键歧义；历史冲突需单独迁移，不静默改号或改资源归属。

### 0.2 登录与交流资格分开

| 场景 | 所需验证 | 完成后的行为 |
|---|---|---|
| 浏览公开内容 | 游客可用 | 不索取手机号 |
| 注册、普通登录、登录态恢复 | 验证所选邮箱／密码／第三方凭证；不强制短信 | 进入同一账号；没有手机号不阻断普通登录 |
| 首次发帖、评论／回复、发送私信／群消息等对外交流 | 已登录且当前绑定手机号已验证；未满足时引导短信核验 | 保留原对象与输入，验证后返回编辑处，由用户再次明确发布／发送 |
| 发布领养／走失信息、提交线索／领养申请、确认预约等对外业务动作 | 同样检查当前手机号验证状态，并继续检查原有业务权限 | 手机验证不替代材料核实、宠物归属或业务授权 |
| 已验证手机号后的正常发帖／交流 | 服务端检查有效验证记录，不重复发送短信 | 不按每条帖子、消息或每次登录收费验证 |
| 更换手机号 | 验证当前账号及新号码；原号仍可用时验证原号，原号不可用走独立恢复 | 成功后保持原 `user_id`，撤销旧号登录关联并绑定新号 |
| 更换邮箱、修改密码、解绑／恢复等安全动作 | 验证当前账号与有关新标识；按动作采用邮箱、密码、已绑定第三方或必要的短信再验证 | 普通登录会话不能单独授权更换登录标识 |

手机号验证状态必须由服务端记录并与当前号码绑定，不能从非空手机号、旧版资料或客户端开关推断。所有相关写命令在服务端执行相同关卡；不能只靠按钮隐藏、客户端判断或旧令牌中的过时状态。解除／失效后停止新增交流，重新验证成功后恢复，已有内容仍遵循原有可见性和处置规则。

换号失败、验证码错误、号码被其他账号使用时保留原绑定与权限，不创建新账号、不迁移聊天和内容。新号码已被占用时提供登录原账号／恢复支持，不披露另一账号资料；拥有新号码本身不能夺取既有账号。原号不可用的恢复须有独立证据核验，不能只凭当前登录态跳过。

### 0.3 实施与验收边界

- 邮箱注册／验证码发送、三标识登录解析、绑定邮箱／换绑、手机号验证记录与服务端交流关卡属于待实施合同；现有 `auth/phone` 自动建号等旧行为不代表新方案已完成。
- 邮箱与短信验证码都需要单次使用、分用途、有效期、尝试上限、频控与发送费用限额；验证码、邮箱及手机号不进入公开资料或分析日志。登录失败不泄露标识对应的其他账号信息。
- 换号／换绑等安全变更沿用单次再验证与既有会话撤销规则。不能解绑最后一个可用登录方式，不能因手机号变更丢失原账号数据。
- 必测情形：三种标识登录同一 `user_id`；昵称重名；大小写／号码格式等价；并发抢绑；未验证邮箱不能登录；未验证手机号可登录但不能绕过交流关卡；手机验证后重复发帖无短信；换号失败不破坏原绑定；换号后旧号不能再登录原账号；恢复不自动发布草稿；历史未验证号码不直接获交流资格。
- 2026-10-20仅更新规则与交接；2026-10-21已同步Figma账号／邮箱／当前手机号及年龄监护设计，未修改服务端、数据库迁移或客户端。未运行编译，遵循全局不自行编译规则；实际测试与供应商联调未验证。

## 1. 平台入口

| 平台 | 通用方式 | 第三方方式 | 备用 |
|---|---|---|---|
| Android | 账号名／邮箱／手机号＋密码；邮箱验证码 | 微信登录、QQ登录 | 手机短信用于交流资格、换号与必要恢复，不作为日常强制步骤 |
| iPhone | 账号名／邮箱／手机号＋密码；邮箱验证码 | 微信登录、QQ登录、通过 Apple 登录 | 同一账号；第三方登录不自动取得手机验证状态 |
| 游客 | 公开浏览、搜索和查看公开资料 | 无需先授权第三方 | 发布、私信、申请等操作发生时再引导登录，安全／隐私报告保留免注册通道 |

微信和 QQ 在两种手机上都规划；Apple 登录为 iPhone 的明确需求。第三方入口与普通登录入口在同一屏可发现，不藏在“更多”里。沿用 M&D 已选 Friendly 字体、间距与中性背景；现有 Figma 使用可编辑矢量品牌标志作位置稿，生产接入使用各平台官方资产与组件。

邮箱验证码入口可使用“登录 / 注册”，创建前明确告知并取得协议同意。普通密码登录使用“账号名 / 邮箱 / 手机号”标识输入。交流触发的手机号页面明确显示“验证手机号后即可发布／交流”；换号页明确显示正在修改原账号的绑定，不沿用“未注册手机号将自动创建账号”的旧文案。保留“先逛逛”和清晰返回。

iPhone 的 Apple 入口按 Sign in with Apple 官方样式规划；当前 Figma 是矢量位置稿，生产使用官方按钮及系统授权面板。按钮与其他快捷方式同屏、文字可读，在官方允许的尺寸与形状范围内映射当前手机控件规范。[Apple 界面指南](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple)

## 2. 一次登录的完整过程

1. 用户从当前任务进入认证，保存站内返回目标和本地草稿引用；不带验证码、令牌或私密正文进入 URL。
2. 用户明确同意本次所需协议／隐私告知，默认不勾选；与营销、GPS、相册、通知授权分开。
3. 选择账号名／邮箱／手机号＋密码、邮箱验证码、微信、QQ，或 iPhone 的 Apple；仅启动用户选择的方式，不额外强制短信。
4. 服务端验证凭证后解析唯一登录标识或稳定第三方身份与 M&D 账号的关联，不能把输入的邮箱或 SDK 回调的昵称当作验证成功。
5. 已关联账号直接登录；首次使用的新身份进入轻量确认：“继续并创建账号”／“我有账号，去关联”。昵称和头像可之后补，不强制建宠物档案。
6. 首次选择关联时，验证已有 M&D 账号，再明确显示将关联的方式与本人账号；验证失败或取消不覆盖现有资料。
7. 登录成功返回原任务并重新检查资源状态、当前手机号验证状态与业务权限；需要交流但尚未验证手机号时引导补充验证，只恢复编辑，不自动发布、发送消息、提交申请、开启提醒或确认预约。
8. 原内容已删除或权限变化时，说明原因并保留可保留的本地草稿，给出安全出口。

首次新身份需要告知正在创建新账号，并提供关联已有账号的机会。这能减少一人误建多个账号；Apple 官方同样建议明确新建与已有账号关联。[Apple 认证与防重复账号说明](https://developer.apple.com/documentation/signinwithapple/authenticating-users-with-sign-in-with-apple)

[认证流程图源文件](flows/mobile-auth.mmd)；可视化流程同时见[认证与冷启动图](flows/cold-start-and-auth.html)。

## 3. 邮箱注册与手机号验证

- 验证码支持系统自动填充、粘贴、修改号码和可读的重发倒计时。发送中防重复；频控、有效期和尝试上限由服务端决定，具体数值由实施配置。
- 邮箱验证成功且同意条款后才可创建或登录相应账号；已有绑定邮箱指向原账号。手机号绑定／换号是原账号管理动作，不通过再次注册悄悄新建账号。
- 短信未到、号码格式错误、验证码不符、过期、发送频繁、网络失败分别反馈；不要每秒向读屏播报倒计时。
- 生产不得使用开发固定码或日志验证码。客户端展示“已发送请求”与供应商实际送达应分清。
- 账号名／邮箱／手机号＋密码统一解析到原账号。找回密码优先使用已验证邮箱等可用恢复方式；必须有真实链路后才显示为可操作，无恢复能力时说明实际支持渠道，不提供演示口令。
- 退出账号后可继续游客浏览；下次登录恢复本人资料，账号切换时清理上个账号的私密缓存。

## 4. 微信、QQ 与 Apple 的专属状态

| 方式 | 正常操作 | 必须覆盖的恢复与边界 |
|---|---|---|
| 微信 | 用户点按后调用官方移动应用授权；回到 M&D 由服务端验证并匹配账号 | 未安装／客户端不兼容、取消、拒绝、授权过期、回跳丢失、网络失败；提供手机号和 QQ 替代，不能循环拉起 |
| QQ | 使用 QQ 互联官方 SDK；正常授权后回 M&D | 区分完成、取消和错误回调；未安装及回跳异常可换方式；浏览器回退仅在所选 SDK 官方支持且完成配置时提供 |
| Apple | 使用系统授权，可用系统允许的认证方式，并处理隐藏邮件地址 | 用户取消、设备条件不满足、凭证失效／撤权、无姓名或邮箱；缺可选资料不阻断合法账号 |
| 任意方式 | 已知稳定身份登录同一 M&D 账号 | 账号被限制、会话过期、绑定冲突、连续点按与重复回调；错误不能创建重复账号 |

QQ 官方文档区分完成、取消、错误回调，说明已安装 QQ 时的 SSO 及授权后返回应用，也提供 OpenID 等返回数据；这里只据此规划恢复状态，不指定 SDK 版本。[QQ 官方 Android 接入](https://wiki.connect.qq.com/qq%E7%99%BB%E5%BD%95)

Apple 用户可以隐藏邮箱，应使用其稳定用户标识进行关联；姓名等资料并非每次授权都重新返回，不能以空姓名覆盖已有昵称，也不能用相同邮箱自动合并账号。[Apple 身份信息说明](https://developer.apple.com/documentation/signinwithapple/receiving-a-users-identity-token)

Apple 审核指南 4.8 对符合其条件的第三方主账号登录要求提供具备相应隐私特性的等价登录选项；本产品按用户要求选择 Apple 登录。不要把该条简化成对所有应用无例外的判断。[Apple 登录服务规则](https://developer.apple.com/app-store/review/guidelines/#login-services)

微信官方入口为[移动应用微信登录指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html)。本次正文读取失败，未核实其当前 SDK 版本与审核细节；实施前再复核申请资质、应用配置和回跳要求，不据此填入未经验证的参数。

## 5. 账号绑定、换绑与恢复

同一个 M&D 账号可以关联唯一账号名、邮箱、手机号，以及微信、QQ、Apple。宠物、日记、好友、群、申请与走失事件都属于稳定 M&D `user_id`，不属于某个邮箱、电话号码或登录按钮。

| 情况 | 处理 |
|---|---|
| 已登录账号绑定一个未使用的第三方身份 | 说明目标账号，必要时重新验证当前会话；授权成功后明确确认并记录 |
| 身份已经绑定其他 M&D 账号 | 不覆盖、不静默合并；提示使用原方式登录，或进入恢复支持；不泄露另一账号资料 |
| 两个已有账号都存在内容 | 首版不自动合并宠物、聊天和权限。显式选择要登录的账号；后续合并另做可恢复方案 |
| 相同昵称、头像、邮箱 | 不能作为同一人的充分依据 |
| 解绑某方式 | 明确影响并再验证；至少保留一种已验证且可使用的登录方式 |
| 最后一个方式无法使用 | 先增加替代方式或走恢复流程，不能解绑后把用户锁在账号外 |
| 更换手机号 | 验证当前账号、可用旧号和新号码；旧号不可用时提供独立恢复，新号冲突不覆盖，成功后仍是原 M&D 账号 |
| 绑定／更换邮箱 | 验证当前账号和新邮箱，标准化后唯一；失败保留原绑定，不按相同邮箱自动合并第三方账号 |
| 第三方撤权 | 标记对应方式需重新授权；允许本人通过其他已绑定方式登录，不自动删除 M&D 账号 |
| 注销 M&D 账号 | App 内发起、说明影响、再验证、处理进度／失败重试和完成结果；关联授权按平台要求处理，必要记录保留规则另行定义 |

第三方授权不能自动等同于手机号或发布资格核验。具体功能若需要补充验证，在动作发生时说明用途并处理；不默认把每种快捷登录都强制改成先填手机号。

## 6. 原任务恢复矩阵

| 发起入口 | 登录后落点 | 仍需用户明确执行 |
|---|---|---|
| 圈子／公开动态／日记草稿 | 原草稿、原宠物、原受众与所选照片 | 发布 |
| 评论／回复／私信／群聊 | 原对象及原回复目标；权限变化则说明 | 发送／发布 |
| 领养申请 | 同一宠物与申请草稿 | 检查共享范围并提交 |
| 预约／变更 | 同一版本；版本改变则先展示差异 | 确认或拒绝 |
| 走失／拾获／目击线索 | 原事件或草稿，保留公开／私密区分 | 提交、公开或结束 |
| 区域提醒／收藏 | 原设置或原内容；不顺带授权通知和定位 | 开启或收藏 |
| 安全／隐私报告 | 保持免注册路径可用 | 自主提交 |

返回目标采用允许的站内路由；过期、无权限、跨账号草稿、冷启动回跳和重复回调都需要保护。登录成功不代表上一个业务操作已经成功。

## 8. 实施依赖与当前事实

2026-10-19原入口见[手机评审交接](figma-study/MOBILE_FIGMA_REVIEW_2026_10_19.md)；2026-10-21已按三个唯一标识、邮箱、当前手机号关卡与年龄监护更新原稿及增补稿，精确节点见[修订账本](figma-study/design-closure-2026-10-21-state.json)。第三方仍需官方按钮／SDK与真实回调，固定状态跳转不代表服务已接入。

历史客户端静态对照：Expo 登录按钮提示第三方暂未开放；Web 的 social 按钮走 coming 提示；KMP 的本地绑定开关不构成服务端身份关联。2026-10-20 新增 v2 服务源码已有手机 OTP、密码及第三方适配入口，但缺少本文新邮箱登录及统一交流前验证合同；源码存在不代表编译、供应商联调或功能验收通过。

实施需要：真实邮件与短信通道、三标识唯一性与历史迁移、邮箱验证与恢复、当前手机号验证记录及服务端交流关卡、各平台应用登记与回跳配置、官方 SDK／Apple capability、服务端凭证验证与稳定身份映射、协议版本记录、会话与账号恢复、账号注销、跨账号缓存清理。App secret、签名私钥与第三方长期令牌只在受控服务端管理；不写入原型、仓库或客户端常量。

产品层推荐识别键为 provider＋平台应用／签发方范围＋provider subject，再关联 M&D user ID。微信／QQ 的 OpenID、UnionID 可用条件在实施时逐平台确认；不能跨平台假定相同字符串代表同一人。

验收覆盖：第0节三标识唯一性与交流资格场景、邮箱验证／密码登录／恢复、微信／QQ／Apple新老用户、首次关联、已有绑定冲突、取消／拒绝、未安装、无网络、重复回调、重装或换设备、Apple隐藏邮箱与缺可选资料、会话过期、旧账号密码迁移、换号、解绑最后方式、撤权、注销和每条返回任务。新认证规则尚未实施；未运行编译、接入SDK或执行设备测试。
