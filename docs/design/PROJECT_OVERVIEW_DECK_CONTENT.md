## Slide 2: 问题陈述与背景 (Problem Statement)
- **核心痛点**：
  1. **信息与身份冒用**：流浪领养与猫舍交易中，发布方、猫咪实际照护方、接待方常出现“货不对板”或中介隐瞒。
  2. **费用模糊与二次加价**：线下到访后常出现捆绑消费、隐形费用、定金纠纷。
  3. **缺乏全程可信记录**：沟通分散在微信、朋友圈，缺乏从“线上预约 -> 线下到访核对 -> 领养交接 -> 30天回访”的结构化追溯。
- **M&D 解决思路**：
  - 以社区与领养为主线，单猫稳定档案为抓手。
  - 实行分项核验（对象、事项、方式、时效透明可见）。
  - 双向快照确认预约，保护双方知情权与退出权。

## Slide 3: 产品定位与设计原则 (Product Principles)
- **产品名称**：M&D (`meow & doggie`)
- **原则一：猫咪优先，犬系友好 (Cat-first, Doggie-friendly)**
  - 核心情绪价值与主叙事以猫咪为中心，犬系作为活跃伙伴分支拓展至户外与增值服务。
- **原则二：温暖亲切，克制可靠 (Warm & Trustworthy)**
  - 采用 Honey / Mint / Night / Neutral 四套主题色彩体系；拒绝过度幼态或杂乱渐变，卡片保持 16px 圆角。
- **原则三：事实导向，不做虚假全包承诺 (Evidence-based)**
  - 不打虚假的“100%全网保真”，而是清晰陈述“平台核验了什么、未见证什么”，分项真实呈现。

---

## Slide 4: 核心功能支柱 (Core Pillars)
1. **纯粹宠友圈 (Pet Moments)**
   - 双向好友关系、纯时间序、逐条私密/公开可见性控制。
   - 内置统一表情包与同一角色猫咪贴纸，支持轻量点赞与互动。
2. **可信领养闭环 (Adoption Loop)**
   - 档案建立 -> 资格申请 -> 线上预约 -> 线下试养与交接 -> 30天成长回访与脱敏故事。
3. **透明找宠与披露 (Transparent Trade / Assistance)**
   - 商业与个人严格标识；地点、预计收款方、健康说明单猫逐项披露。
   - 变更版本重新确认，拒绝不计违约。

## Slide 5: 系统架构与技术实现 (Tech Architecture)
- **后端**：Go 语言微内核结构，清晰的领域实体分层（`User`, `Pet`, `AdoptionPet`, `Post`, `Appointment`, `Report`）。
- **前端与跨端客户端**：
  - Web UI：高保真响应式静态原型与展示面板。
  - Mobile (React Native / Expo & KMP Android)：对齐 Stitch V2 与 Figma 设计稿的原生组件与认证流（手机号、微信、QQ、Apple ID）。
  - Desktop (Compose Desktop)：8dp 控制面板与紧凑工作台。
- **设计中枢**：Figma 原生稿作为视觉权威，Stitch V2 维护工程设计系统。
