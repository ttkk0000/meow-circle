# M&D 真实性、披露与预约规范

版本：1.1｜更新：2026-10-16｜状态：待实施规格；新增领养核验与举报有效性规则

适用：领养与找宠共用信任能力，猫咪优先，兼容狗狗与其他允许物种；需求优先级以 [PRD](../bmad/prd.md) 为准。武汉／上海冷启动与外部信息另见[增补规范](MND_COLD_START_LOST_PETS_AND_AUTH_SPEC.md)。

## 1. 核心规则

个人、商家、猫舍、救助者和公开关系的代理均可发布其获授权的信息。平台核对主体、关系和具体事项，不评定“家庭比商家可信”，不把中介存在本身认定为欺骗。

账号类型、对某只猫的关系、核验结论是三个独立维度。一个商家可以发布救助领养；同一账号对不同猫的关系也可能不同。

## 2. 每条信息需要披露的关系

| 字段 | 要求 | 公开范围 |
|---|---|---|
| 发布账号与主体 | 个人或经营主体、代表人员授权 | 对外名称与具体核验项；证件不公开 |
| 信息性质 | 救助领养、个人送养、出售/有偿转让 | 列表与详情持续可见 |
| 当前照护方 | 现在由谁照护、与发布者的关系 | 主体展示名及城市区域 |
| 来源说明 | 自有、繁育、受托、转入等；未知项如实标记 | 脱敏摘要与材料状态 |
| 发布关系 | 直接发布、员工发布、受托代售、其他代理 | 摘要不可折叠隐藏 |
| 接待方与看猫地点 | 谁接待、场所类型、与照护方的关系 | 地区/场所类型公开；精确预约地址按权限展示 |
| 预计收款与责任方 | 卖家声明的预计收款主体、费用归属、售后联系人 | 交易双方在预约前可确认；不展示完整金融账号 |
| 代理费用 | 有无、金额或计算方式、由谁支付、何时发生 | 报价与预约确认中列明 |

这些主体可以不同，但相关授权、关系和责任必须说清。商业主体依法需公示的信息不能以“家庭隐私”模板统一隐藏；公示与个人地址权限分别配置。

## 3. 分项核验

每项结论至少记录核验对象、事项、方法、时间、审核人/来源、有效状态和适用版本。

| 结论名称示例 | 意义 | 不代表 |
|---|---|---|
| 账号主体已核对 | 账号与提交主体材料相符 | 猫属于该主体 |
| 发布授权已核对 | 该账号有相应发布权限 | 可不经确认转给其他商家 |
| 猫咪近期视频已审阅 | 指定任务材料通过完整性检查 | 已证明所有权、繁育来源或健康 |
| 场所材料已核对 | 材料支持所述接待场所及关系 | 平台实地检查过每个房间 |
| 医疗材料已上传 | 有文件但未向出具方确认 | 已核验疾病或保证无病 |
| 医疗材料来源已确认 | 指定出具方确认某份材料 | 未来健康保证 |
| 买家反馈信息一致 | 有关联预约的买家提交该反馈 | 平台实地见证或付款确认 |

证据状态与 PRD 对齐：missing（未提供）、pending（待审）、needs_changes（待补充）、valid（有效）、rejected（未通过）、expired（已过期）、revoked（已撤销）、disputed（存在争议）。不把“未上传”当“审核失败”；也不把“材料存在”当“来源已核验”。

待补充或未通过可重新提交至 pending；过期、撤销或存在争议的材料需复核后才可回到 valid，不靠用户重新上传或时间推移自动恢复。

推荐试点参数：宠物动态材料超过 30 天需更新；主体/授权到期或关键关系变化立即复核。期限属于可配置产品假设，不能用其替代适用规则要求。

## 4. 近期验猫与材料最小化

- 平台给出限时任务和随机码，材料需关联单只猫、时间和当前环境。
- 允许平台视频通话、人工见证等替代方式；不要求用户为拍摄而暴露整屋、门牌或家庭成员。
- 原始证据仅限必要审核与争议人员访问；公开版去除人脸、住址、金融账号等无关信息。
- 相似图片、定位、EXIF 和多账号关联只作复核信号，不能自动判定盗图、串通或欺骗。
- 个人送养与救助不强求母猫/同窝资料；商业繁育如声明相关来源，应为声明提供适用证据，未知不得伪造。

## 5. 价格与条件

出售/有偿转让必须披露单只猫价格、币种、所有已知必付项及总额、可选项目、订金或预付款条款（如有）、售后责任与已知健康情况。

预约前不能只显示“低至”“到店再说”而隐藏必须费用。涉及买家选择的服务，先确认选项后保存具体报价版本。未选择项目不得计入“可选低价”掩盖最低实际支出。

领养不能承载隐藏售猫或捆绑消费。若有合理医疗支出，应展示类别、金额/上限、凭据与处理约定；收费性质不清时转人工审核。本版规划假设是 MVP 不代收任何一条通道的猫款，支付服务尚未由用户决定，不能据本文实施收款或承诺担保。

## 6. 预约确认快照

每次预约以不可覆盖的版本保存：

- 猫的稳定标识、关键特征、当前资料版本和代表媒体；
- 信息性质、发布者、照护方、接待方及代理关系；
- 时间、看猫地点、场所类型与精确地址的授权范围；
- 当前报价、必付项、总额、预计收款方、代理费；
- 已知健康情况、材料时效、交接与售后约定；
- 双方确认时间、版本和下一步。

只有双方确认同一版本才成为“已确认预约”。对方拒绝或未回复时保持待确认，不以超时默认同意。

## 7. 变更与到场保护

2026-10-21本节与[安全生命周期合同SC-AP](MND_SAFETY_AND_LIFECYCLE_SPEC.md)共同使用，普通改约与安全关键事件分开；年龄、单独占试养／候补、安全接回和数据期限以该合同为现行增补。

| 变化 | 系统行为 | 用户出口 |
|---|---|---|
| 地点、接待主体、猫、总价/必付项、预计收款、代理、已知健康或交接/售后责任变化 | 生成新版本；旧确认不再覆盖新安排 | 接受、拒绝、取消、举报 |
| 时间变化 | 新版本重新确认并通知 | 接受或改约 |
| 买家现场主动换猫 | 新猫建立独立关联确认，不覆盖原猫 | 保留原预约结果 |
| 对方要求私聊变更 | 提示回平台更新，保存用户提供的必要证据 | 退出或提交不符反馈 |

平台记录同意与拒绝，不能物理阻止现实中的转场。拒绝新版本的用户不能被记作无故失约或降低买家信誉。

普通改约保留原effectiveVersion，待确认提案不覆盖它；提案过期只结束提案，不能自动采用新地点。原地点不可用、主体／宠物不符、健康重大纠正或隐藏费用等具体安全风险进入safety_hold，明确暂停按原安排出发。风险解除后核对并双方确认新版本；不能靠撤回提案恢复危险安排。预约取消、未到访、未回应和争议分别记录，不自动归咎买家。

## 8. 到访、交接和反馈

到访码仅用于关联预约，不单独证明到场。双方分别提交到访结果；买家按猫、身份/接待方、地点、报价及必付项分别选择一致、不一致、不确定，允许未成交但信息一致。

卖家自报成交、双方确认交接、用户提供支付凭据分别记录。未接入支付时不显示“平台已核验付款”，也不提供未经授权的担保或赔付承诺。

评价显示依据类型：有预约记录、有到访反馈、有双方交接确认。没有记录的用户仍可举报，不应因为缺少到访码失去维权入口；公开评价的证据等级与投诉资格是两件事。

## 9. 投诉、复核与申诉

报告沿用 PRD 状态值 received、reviewing、upheld、not_upheld、inconclusive、closed、appeal、reconsidered。本次将 received 的对外文案细化为“已收到（待分流）”，避免自动回执冒充人工核实；其余依次为“待核实”“不符已确认”“报告未获支持”“无法判定”“已结案”“申诉中”“已复核”。“未获支持”不能简化为“证明没有欺骗”。举报数量和单方陈述不直接产生“骗子”公开标签。

申诉从原结论关联进入 appeal，再由授权人员复核并保存新结论；不覆盖旧证据。恢复发布或核验必须满足对应门槛，不能仅因投诉结案自动恢复。

审核比较预约版本、材料、变更与双方说明；必要时暂时停止新增预约或隐藏内容，并告知原因与补充通道。卖家不能删除有效负面反馈；平台脱敏展示必要处理结果，避免公开证件、地址或未核实指控。

重复异常可以触发关联复核，但员工共用门店、同场所多猫、合法代售不应被自动封禁。保留申诉和改判记录。

## 10. 数据与权限

| 数据 | 访问主体 | 处理要求 |
|---|---|---|
| 公开档案与脱敏核验摘要 | 访客/用户 | 可分享；敏感字段不进入公开响应 |
| 预约精确地址与接待安排 | 预约双方及授权工作人员 | 确认流程中按需授权；访问留痕 |
| 身份/授权原件、原始视频 | 指定审核/争议人员 | 隔离存储、最小权限、不写入分析事件 |
| 预约快照、确认与争议记录 | 相关双方及授权工作人员 | 不可静默覆盖；保留期依据适用义务制定 |
| 金融信息 | MVP 不收集完整账号和支付凭据作常规字段 | 个案证据先脱敏，再按需受理 |

撤回申请或注销不自动销毁争议中、依法需保存的证据；非必要家庭资料应及时删除或隔离。现行[数据期限与权利合同SC-DATA](MND_SAFETY_AND_LIFECYCLE_SPEC.md)规定分项设计默认值、保全例外和备份处理，生产数据清单核定后才能发布正式政策，不照搬一个统一年限。

## 11. 最低可用闭环

首轮必须能回放：发布信息 → 核验摘要 → 预约快照 → 变更与确认 → 到访反馈 → 举报复核与申诉。其他功能可延后，但不能只上线“认证章 + 私聊”。

本规范是拟实施规则。当前代码差距、需求 ID 和阶段范围见 [PRD](../bmad/prd.md)，页面结构见 [UX 规格](../bmad/ux-design.md)。

## 12. 领养信息的“真实”怎样表达

不设置笼统的“真实领养／100% 真实／健康保证”徽章，也不以总分给发布者永久背书。在列表显示具体且当前有效的事项；详情设置“真实性与领养说明”和“信息有误／举报”两个常驻入口。

| 事项 | 可采用的核对方法 | 公开文案及边界 |
|---|---|---|
| 账号可联系 | 完成生产环境有效认证，异常账号必要再验证 | “手机号已验证”；不等于该人拥有这只宠物，不公开号码 |
| 与具体宠物的关系 | 送养／照护／救助／受托关系声明；适用时核对照护链、委托记录或组织授权 | “发布者声明：受托照护”；只有实际核对授权后才能写“发布授权已核对” |
| 近期接触及对应宠物 | 平台任务码视频、人工视频通话、合格合作人员见证等可替代方式 | “近期视频已审阅 · 日期”；支持近期接触与外观对应，不证明归属／健康／排除代理 |
| 已知健康信息 | 逐项填写已知／未知、检查日期、材料与出具机构；经适用授权向可信机构渠道确认材料 | “材料已上传”与“某份材料来源已确认”分开，不能写“保证无病” |
| 条件与费用 | 逐项披露条件、全部必付项、分摊凭据及交接约定；与申请／会话记录核对 | “无必付费用”或“含医疗支出分摊 ¥X”；有必付项不能宣传“完全免费” |
| 当前可领养状态 | 发布者定期确认；关联申请、交接或复核事件 | “发布者于某日确认仍可申请”；不是平台持续现场确认 |

电话、视频、机构材料、预约和回访各自形成证据，不因通过其中一项自动点亮其他核验项。不以粉丝量、是否家庭饲养、是否商家、举报少或发布历史长作真实性结论。

### 12.1 发布门槛与低资源替代

1. 提交时必须明确发布关系、具体宠物、照护区域、信息性质、已知／未知健康信息、条件、费用及可联系账号。资料不全先存草稿，逐项说明缺什么。
2. 开放正式申请前，应有至少一种支持近期接触与具体宠物对应的材料及必要关系核对。视频不是唯一入口，可走人工或已确认合作机构见证；医疗、血统、芯片和整屋拍摄不作所有送养者的统一前置条件。
3. 无医疗记录可如实写“未检查／暂无材料”，不要求虚构疫苗或病史。重要矛盾、疑似来源侵权、隐藏收费进入人工复核，不把“健康未知”自动当作欺骗。
4. 紧急救助且暂时无法补齐的，提供独立“求助／待补核验”路径，明确性质与限制，不伪装已核验领养，不直接放行未核对的交易／交接承诺。
5. 拍摄不要求展示家庭成员、门牌或完整住宅，不为完成任务强迫宠物做危险动作。材料经授权、最小化保存，公开页只显示脱敏摘要。

### 12.2 时效与变更

沿用第 3 节近期动态材料 30 天更新的试点假设；发布者可用状态建议每 7 天确认一次，未确认写“状态待更新”，不自动标记已领养。期限均为运营建议，需按供给和审核能力调整。

换宠、换照护／接待关系、健康纠正、费用或条件变化保存新版本，并按影响暂停新申请或新增预约；通知受影响申请者并保留退出权。核验到期、争议与撤销只影响相应事项，是否限制整条信息依具体风险决定。重新上传不自动恢复有效。

## 13. 举报如何收集到有效信息

入口在详情固定可达，图片、会话和申请／预约记录也能发起；可选择“指出信息错误”或“举报风险”，不强迫普通纠错者先给对方贴诈骗标签。没有申请、预约码或账号也保留安全举报及隐私投诉通道；登录用户可自动关联其有权访问的记录。

| 举报类型 | 优先核对内容 | 提交者不必承担的义务 |
|---|---|---|
| 盗图／宠物不对应 | 本平台发布快照、原来源时间与使用许可、被指出的具体特征 | 不必证明对方全部身份或公开自己住址 |
| 冒用救助／送养身份 | 该宠物关系声明、授权及照护方解释；必要时向原授权方独立核对 | 不要求举报者自行联系或对质潜在欺骗方 |
| 隐藏收费／捆绑消费 | 发布时费用版本、具体被要求的必付款／物品、相关会话 | 没付款也可举报，不要求先交易受损 |
| 换宠／临时转场／接待方变化 | 原快照、新安排、双方确认与当事人反馈 | 拒绝转场不能被计为失约 |
| 已领养仍引流／状态失实 | 交接与状态记录、更新时刻、发布者补充 | 重复图片只能触发复核，不能独立证明重复出售 |
| 健康描述矛盾／材料疑点 | 原“已知情况”、指定材料、事发与检查时间；必要时专业复核 | 不要求用户自行下医学诊断；事后出现问题不自动证明先前欺骗 |
| 位置／联系方式／证件泄露 | 被暴露的具体字段及访问范围 | 不用再公开上传完整敏感原件才能请求隐藏 |

默认关联平台已持有且提交者有权使用的内容版本；让用户写“哪一点不一致”，时间、链接、截图或凭据可后补。原始文件不公开给围观者；公开摘要不得暴露举报者身份，必要披露给被举报方前先评估安全与最小范围。

服务端保存提交时的关联发布版本，记录证据来源、提交／获取时刻、访问与修改历史。用户上传的截图注明“用户提供”；哈希只说明文件是否变化，不证明内容真实。撤帖不销毁已进入受控争议处理的必要记录。

## 14. 举报处置：分流、核实与救济

1. 自动给“已收到”回执、编号、补充入口与当前服务时段；不得伪装工作人员已核实。承诺首次响应时限前必须有真实值班能力；非服务时段明确说明。
2. 按隐私暴露、潜在持续损害、事实矛盾等分流。存在具体高风险依据时可先隐藏敏感字段、暂停该条新增申请／预约；临时保护不是最终定性，账号其他能力不无差别连坐。
3. 比较原版本、独立来源、双方说明与必要第三方确认。来源相互复制不算多份独立证明；向机构核对时不只使用被争议材料中给出的陌生联系电话。
4. 给发布者合理的说明与补充渠道，同时保护举报者；未回复可以触发明确的服务限制，但不能单独等同“诈骗成立”。
5. 分别结论为“已确认某项不符／未获支持／无法判断”，写明范围、依据摘要、采取动作和下一步。情况纠正、标记某项过期、转商业分类、隐藏内容或账号处置须与事实及严重性相称。
6. 双方能查看与自身有关的脱敏结果并申诉；高影响、利益关联或改判案件尽可能交不同审核人复核。保留原结论与改判原因，不以结案自动恢复旧核验章。

举报数量只用于排队和关联检查，不能凑到一个数就自动封号，也不靠“付费认证／高等级账号”抵消有据风险。重复提交可合并工单但保留每个举报者回执；协同骚扰、垃圾证据、明显伪造分别处理。一次未获支持或无法判断，不等于恶意举报，不能因此惩罚用户正常维权。

## 15. 怎样判断核验和举报机制真的有效

不能用“认证通过率高”“举报量少”“处理量多”作为安全成功的唯一证据。建议试点维护以下指标，按武汉／上海、原生／转载、问题类别分别看；样本少时披露样本量，不做精确找回／防骗率宣传。

| 指标 | 定义与解释 | 防止误读 |
|---|---|---|
| 核验抽检差错 | 随机抽检中，核验范围、证据时效或公开标记存在错误的个案／抽检个案 | 同时抽通过、拒绝和未举报内容，避免只看投诉样本 |
| 有效更新覆盖 | 仍公开且可申请的信息中，关系／近期接触材料及可用状态按规则有效的占比 | 不因大量下架让分母变小而宣称改善；并列显示下架量 |
| 首次人工响应与处理时长 | 从收到到首次实质人工回应、最终结论分别计算，区分服务时段与自然时长 | 自动回执不算人工响应；待补材料与高风险保护时间单列 |
| 证据充分度与结论分布 | 各类报告可核实所需字段是否齐全；获支持／未支持／无法判断占比 | “无法判断”多需改善取证，不强行判成无问题以结案 |
| 申诉改判与处置一致性 | 有结论申诉中的改判量与原因；相同事实能否得到一致规则应用 | 不把改判为零当作目标，不阻碍申诉降低数字 |
| 重复问题与实际反馈 | 同一案例纠正后再次发生的同类问题；申请、交接与自愿回访中的信息不符反馈 | 平台外未反馈不能记为“无欺骗”；双方确认也不等于平台见证 |

首发前人工回放至少覆盖：真实送养、受托救助、无医疗材料、视频过期、隐藏必付费用、盗图疑点、无码举报、隐私泄露、无法判断和申诉改判。这里只定义验收用例，本轮没有执行实际测试。

## 16. 领养核验与举报的新增验收条件

采用独立增补编号，不覆盖 PRD 既有需求编号：

- TR-AD-01：每个公开标记能展开对象、方法、日期、当前状态及“不代表什么”；未实际完成认证或核对不得显示通过。
- TR-AD-02：一次授权只适用于对应宠物／发布关系；商业、个人、救助均能如实披露，不能以账号类型替代核验。
- TR-AD-03：费用非零时，“完全免费”不可用；未知健康项与无材料可诚实呈现，不能生成虚假健康认证。
- TR-RP-01：无申请／预约码可举报，安全渠道不强制注册；系统保留必要内容版本，用户能补充并查看回执。
- TR-RP-02：收到回执与人工核实分开；临时保护、事实结论、处罚与申诉各有记录。
- TR-RP-03：不因举报数量直接公开定罪；不因未获支持认定恶意；申诉保留原记录与改判理由。
- TR-RP-04：发布者不能自行删除负面处理记录，举报者看不到他人私密原件；公开结果脱敏并给必要纠错／恢复路径。
