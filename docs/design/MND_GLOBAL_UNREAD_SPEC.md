# M&D 全局未读与消息中心设计

日期：2026-10-20。用户要求：补齐全局未读，超过99显示99+，覆盖帖子回复、私信与群消息，先完善UI。视觉沿用现有Figma手机V2默认浅色、Noto Sans SC／Manrope、现有导航和组件；不改生产Stitch合同。

## 数量与入口

- 手机底部“消息”为全局入口；Web顶部消息入口、桌面侧栏、平板导航使用同一口径。消息中心分“聊天／互动／通知”，不增加主导航Tab。
- 0不显示数字角标；1–99显示原数；100及以上统一显示`99+`。真实值保留整数，先去重汇总、后格式化；不能把多个99+相加。角标随宽度伸展，不裁掉加号。
- 数字代表未读事件／消息数，不是未读会话数、点赞累计数、待处理任务数。自己发送的内容、重试回执、同一事件的推送和站内副本均不重复计数。
- 示意数据统一为聊天83＋互动16＋通知8＝107，全局显示99+。聊天83＝私信6＋私信12＋群消息62＋消息请求3；互动16＝回复8＋提及3＋赞与收藏5；通知8＝关系邀请3＋业务进度4＋系统1。
- 免打扰群另有124条未读，不加入上述107条提醒合计；“全局全部已读”包含这些会话，因此确认画板处理的是当前231条已知未读。只改变显示口径不等于丢弃免打扰未读记录。
- 未读存在但暂时无法确认精确数时使用状态提示，不能伪造0。离线展示“上次同步”，恢复后重新核对；读屏说明使用未读语义，数字变化不抢焦点或逐条播报。
- 切换账号或退出时清除前一账号未读缓存、角标与导航上下文，游客不显示旧账号数量。本轮99+约束应用内角标；桌面系统图标／系统推送按平台能力另行接入。

## 分类覆盖

| 分类 | 包含内容 | 计数边界与跳转 |
|---|---|---|
| 聊天：私信 | 已接受会话的新文字、图片、贴纸；业务上下文会话 | 打开会话定位首条未读，业务关联不再另生一条重复私信通知 |
| 聊天：群消息 | 群文字、图片、贴纸、@我及公告入口 | @我是定位／优先提示，不在同一会话计数里再加一次；群邀请单列关系通知 |
| 聊天：消息请求 | 陌生人首次联系 | 未读请求与“仍待接受”分开；查看不等于接受，接受后不重复把旧事件计入全局 |
| 互动：回复我 | 帖子、圈子、日记的评论，以及对本人评论的回复 | 去到具体内容和回复锚点；删除／失权给出说明，不泄露原私密内容 |
| 互动：@我 | 内容或评论中的提及 | 同一条同时回复并提及本人时只归一个主事件；群@留在群会话，不再加入互动总数 |
| 互动：赞与收藏 | 实际支持的点赞／收藏互动、新关注等轻互动 | 聚合卡可以显示多个人，但必须按同一未读口径核销；收藏通知依实际隐私／接口能力开放 |
| 通知：关系与邀请 | 好友请求、群邀请、宠物协作邀请、成员／群主变更 | “未读3”和“待处理3”分别显示；读过仍待处理不继续占未读角标 |
| 通知：业务进度 | 领养申请／补充／决定／交接／近况，预约提案／确认／取消，走失线索／认领／区域订阅 | 携带目标与版本；同事件只在一个通知来源计数，私信说明不再复制计数 |
| 通知：审核与系统 | 材料／发布审核、举报／申诉进展、账号安全、服务通知 | 审核收到与结论分开；营销／推荐不默认进入个人未读数字 |

所有分类都是UI覆盖合同，不代表接口或事件已经实现。源功能不存在时显示实际能力边界，不编造关注、收藏、提及或供应商送达。

## 阅读与免打扰（设计建议）

- 进入消息中心不清空所有未读；查看某条通知只核销该条。聊天仅在会话可见、相应内容实际展示后推进已读位置；在看历史时保留“下方有新消息”按钮，不强制滚动或提前清空。
- 提供“仅看未读”、分类全部已读和全局全部已读；明确范围与数量，全局操作包括免打扰会话，确认不会自动接受申请、加入群、确认预约或删除消息。只核销用户确认时已知的事件，操作中新增消息仍未读。
- 已读成功后分类与全局一起减少；失败保留原状态并支持重试。多设备以服务端已读位置和事件标识收敛，不因离线设备回传旧值把计数加回去。
- 免打扰会话保留灰色未读角标／摘要，不计入全局数字；@我／群公告是否例外由可见设置决定。此项为本轮建议，画板明确标注，不将其当作用户已单独确认的规则。
- 静音通知、关闭系统推送、站内已读是三种不同状态；关闭系统权限不丢失站内消息。暂不可达、删除、拉黑、退群等情况不留下永久无法核销的角标。
- 未读与待办分开：业务卡可以已读但仍“待确认”，使用中性状态标签；危险操作不通过标为已读触发。
