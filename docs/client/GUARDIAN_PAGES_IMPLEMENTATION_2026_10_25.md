## 服务端边界

新增五个最小 DTO 和六个消费者操作：读取能力、分页记录、单条记录、创建、领取、取消。新增具名核验人员的分页待核对队列，沿用原 `guardian-evidence` 接口和 `identity_verifier` 角色。

- 创建仅在精确 HTTPS `MND_WEB_ORIGIN`、已有身份密钥和当前生效的正式儿童规则齐备时开放。规则草案或缺配置显示不可用，不造演示邀请码。
- 邀请15分钟有效；HMAC 派生一次性口令，消费者链接不包含儿童资料。口令放在 URL 片段，不发送到 HTTP 请求路径或 Referer。服务端只保存随机 nonce 与口令指纹，领取后清 nonce。
- 同一儿童账号最多复用一个未结束邀请；新客户端编号不会重复创建。创建／领取／取消分别保存原编号与内容指纹；旧对象已清理也不按旧编号新建。取消核对对象及版本。
- 领取必须由独立成年且当前手机号已验证的本人账号完成，只进入最长7天的关系核对阶段。领取不创建 Guardian 记录或权限。
- 具名人员记录已核实证据的最小私有引用时，核对原邀请编号、版本、儿童、领取人、专门规则版本与期限。完成后只产生 `verified_pending_consent`；证据引用不投影给消费者。
- 监护人再核对原规则及必要范围，进行本次 scope／reauth，并主动确认。范围仅 `interaction` 与 `personal_data`，不包含商业、线下签约、营销或公开精确位置。儿童账号无法代点监护人的同意或撤回。
- 未知结果按原编号读取回执；404或网络失败不当作未提交，也不自动重发。完成授权后仍由服务端资格控制具体业务，不自动提交此前草稿。

独立 Web 运营入口新增待核实监护关系队列及证据引用／有效期输入。原邀请、双方账号、版本和规则从当前队列固定带入；消费者 Cookie 不进入运营请求，凭据只在内存。本页面只记录真实核实结果，不以勾选或填写样例生成真实关系。

## 保护动作的实际校验

对照保护稿时发现普通消息请求仍可用于未成年人陌生人私信，现补事务内 `directContact`：只有双方均有有效成年结果的陌生账号可发起普通消息请求；已双向确认的好友可继续受保护日常交流，仍逐次检查发送人的交流资格与屏蔽状态。创建私信、接受原请求和发送新消息都复查，不让旧会话绕过后续年龄复核。统一 `contact_restricted` 不透露对方的年龄分类。

屏蔽、解除屏蔽、拒绝、撤回和移除联系只要求当前有效账号，不因交流资格失效而禁用；解除屏蔽不会恢复好友关系。历史阅读权限、群聊和商业权限沿用各自服务端合同，没有客户端本地放行开关。
