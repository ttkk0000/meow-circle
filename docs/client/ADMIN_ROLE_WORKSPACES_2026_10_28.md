## 已接入源码

| 范围 | 入口与实际行为 |
|---|---|
| 岗位策略 | `web-client/src/operator/roleWorkspaces.ts`：5个业务岗位的页面／队列白名单，4个技术岗位的默认入口和侧栏顺序；没有角色继承或管理员通配 |
| 业务入口 | `OperatorApp.tsx`：只展示本岗菜单和首页，多岗位只可选择本人已获角色；越权直链先进入受限状态，不读取对应详情；切换明确清空未提交输入，准备中／结果未知不可切换 |
| 本岗首页 | `QueuePages.tsx`：仅统计本岗已读队列；资料保护按编号、授权按对象与范围、财务按实际台账；不填假全站总数 |
| 新任务 | `RoleTasks.tsx`：可信年龄区间、授权证据、实际收款／退款；必要字段与预览确认、当前对象版本、原财务请求、明确失败／未知／响应接受分别呈现；字段只在内存 |
| 授权版本读取 | `GET /api/v2/ops/authority`：精确scope、用户／宠物或规范城市／物种读取现有版本，无记录明确exists=false；独立authority_verifier角色及具名读取审计，不增加全量用户或授权目录 |
| 资料失权 | `useOperator.ts`：角色变化取消旧请求；清理失权队列、详情、草稿及准备动作，未知事项只保留必要恢复引用；旧响应不能重新填回材料 |
| 技术后台 | `OpsApp.tsx`、`RecordPages.tsx`、`DetailPages.tsx`：四岗位默认入口与菜单顺序；非对应角色隐藏事件／发布写按钮；ops_admin不会自动取得写入能力 |
| 运维刷新 | `useOperations.ts`、`client.ts`：每次刷新先回读当前身份／环境／capabilities；能力变化取消旧请求、清空采集并使详情重新挂载；写操作仍由服务端角色和精确环境校验 |

年龄没有默认成年选择。授权先读取当前自然键对应版本，修改对象会使旧回读失效；已有记录不能手填版本绕过。实际收支只登记已发生事实，CNY按整数分，退款关联原收款，不执行支付或退款转账。空台账返回null时仍显示已读空状态。

新任务的未知结果冻结本次内容。年龄／授权没有独立操作回执，不自动重发，也不把对象变化认作原操作成功；人工核对后的结束只关闭本机待办。业务与技术会话互不继承，凭据不进入URL或通用持久存储。
