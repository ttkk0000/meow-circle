## 2. 后台设计细化的实际范围

[详细交互合同](../design/ADMIN_TASK_INTERACTION_2026_10_29.md)与[节点／截图交接](../design/figma-study/admin-task-interaction-2026-10-29/README.md)分别维护语义和证据。

- 四类任务均区分填写、完整核对、明确勾选、提交中、接受、明确失败、结果未知与人工核对后关闭本机待办。

## 3. 深入分析新增的实现差距

[事件对齐表](../design/NOTIFICATION_EVENT_ALIGNMENT_2026_10_29.md)详细记录以下事实：

1. 好友request／accept当前是interactions；分类变化还涉及列表、汇总、推送偏好和历史通知，不能只改Tab文案。
2. 当前Pending未统计Friendships和群主转让；群主转让／成员变化也不是所有操作都会产生个人通知。
3. 关注寻宠进展的事件也存在互动／业务通知分类差异，不能把所有cases通知整体改类。
4. KMP显式标为已读、Web列表先读后跳和Web系统通知链接直接跳转存在语义差异。
5. 通知没有独立target_version或回复锚点；不能将通知version用作原业务版本。
6. 历史兼容必须保留原通知ID、已读及送达事实，禁止重复通知／重置已读／重发推送。

这些差距已变为明确的后续实施与验收条目，没有通过新增画板改变服务端权限或线上数据。

320宽、160%大字、200%网页缩放、VoiceOver、焦点及键盘矩阵原已存在，本次继续保留。后续必须按各端实际证据记录，不能用静态映射或Figma截图抵扣。
