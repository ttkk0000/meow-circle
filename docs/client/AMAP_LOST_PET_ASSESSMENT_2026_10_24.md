## 结论与第一期建议

可以实现“在 M&D 地图上标注猫猫最后出现的位置”，现有寻宠记录可以复用。按面向公众运营的商业产品预算，主要固定成本是高德基础版技术服务许可公示价 **5 万元／年**，初期调用费预计远低于许可费。若主体和用途获高德确认适用非商业合作或优惠，再调整预算；不能因寻宠模块带公益性质就直接按免费商用计算。[官方价格](https://lbs.amap.com/upgrade)、[许可适用说明](https://lbs.amap.com/faq/advisory/authorization/43168)。

建议第一期采用自有 HTTPS 地图页：Web 与 Android WebView 共用高德 JS API 渲染、点选和标记组件；业务记录继续存 M&D 服务端。Android 手机和平板使用同一业务状态和地图协议，分别适配布局。后续若地图成为高频核心功能，再考虑 Android 原生地图 SDK。

第一期功能建议为：手动选择最后见到的位置／时间、走失与拾获标记、公开范围圆、按城市／状态／时间筛选、点位与求助卡片联动、点多时聚合、找到或撤回后同步更新。手动选点不依赖读取用户当前位置；“使用我的位置”仅作单次可选辅助。没有宠物定位设备和对应数据源，地图无法追踪猫的实时位置。

这里是在自己的地图页面绘制自有记录，并非向高德地图 App 发布公共 POI，也不会自动让所有高德用户看到寻宠贴；费用模型按地图与服务请求估算，不按“几只猫／几个标点”套单价。[高德自定义点标记文档](https://lbs.amap.com/api/javascript-api-v2/tutorails/add-marker)。

| 源码／合同 | 读取到的事实 | 接入所需工作 |

| [现有位置合同](../design/MND_PRODUCT_CLOSURE_CONTRACT_2026_10_23.md) | 城市／区域优先，可选粗点；展示、定位与导航分别处理 | 延续现有约束，不能把区域中心伪装成最后出现地点 |

当前 Web／Android／服务端均将坐标保留两位小数。纬度步长约 1.11 km，武汉／上海附近的经度步长约 1 km，属于公里级网格，不能称为 100 米精度。若希望在街区范围找猫，建议另行确认公开约 100～300 米范围的规则；这是待确认建议，本轮不修改现有公开精度。已经舍入的历史点无法凭地图恢复精确位置。

目前模型没有明确的 `coordinate_system`。高德使用 GCJ-02，GPS 等来源可能是 WGS-84；应记录来源与坐标系，在明确来源后统一转换，不能把未知历史点一律视作 GPS，或对高德选点二次转换。[官方坐标转换说明](https://lbs.amap.com/api/javascript-api-v2/guide/transform/convertfrom)。距离筛选和订阅也需要使用约定一致的坐标体系。

组件建议分成地图容器、选点器、标点／范围层和记录卡片；表单与状态继续复用已有 MVI／Store，平台地图实现藏在适配层内，避免手机、平板各写一套业务。H5 桥只传公开地图所需字段，校验来源和消息格式；令牌与私密地址不放地图 URL。JS Key 与安全密钥按高德要求配置，生产安全密钥通过服务端代理保管。[官方安全密钥指引](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)。

## 改造工时与维护

以下按一名熟悉现有工程的开发者估算，供应商授权／Key 已就绪，范围为上述第一期功能。包含接线和基本联调；不包含等待采购、现有全库问题修复、全设备验收或实时宠物追踪。

| 方案 | 估计投入 | 取舍 |
|---|---|---|
| 共用 H5：Web＋Android WebView | **5～8 人日** | 地图组件可复用最多；需要处理 WebView 桥、页面生命周期和手势 |
| Android 原生地图 SDK＋Web JS API | **8～12 人日** | Android 交互与生命周期更可控；两套渲染层，业务合同仍共用 |

H5 估算拆分：共享合同／坐标与服务端 1～2 人日，地图页／选点与标点 2～3 人日，Android 容器接线约 1 人日，联调与退化检查 1～2 人日。原生方案对应为 1～2、2～3、3～4、2～3 人日，合计 8～12 人日。人工金额可用“人日 × 项目实际综合日成本”计算，当前没有日成本依据，不编造人民币报价。

Android 原生选型还须核实 SDK 与项目 min API 26／target API 37、ABI 和 16 KB 页大小要求的适配；本轮未下载或运行 SDK。官方轻量版文档说明其基于 JS API，不能仅凭“轻量版”名称认定是独立原生渲染方案或已完成最新 Android 适配。[官方轻量版概述](https://lbs.amap.com/api/lightweight-android-sdk/summary)。

维护重点是密钥／域名／签名配置与配额预警、SDK／JS API 兼容、地图故障时城市列表可用，以及找回／撤回记录同步。搜索防抖、地图实例复用、按视野取自有数据，可减少请求和渲染负担；不为每个标记重复做地址解析。公开精度和坐标转换只维护一份合同。
