# 默认主题、独立平板适配与验收

更新：2026-10-20。本文区分“设计目标”“实现要求”“实际验证”。本轮只有文档，没有新增客户端验证结果。

## 1. 当前主题决定

当前客户端统一使用 Figma 手机主版本 V2 的默认浅色样式。Android、iOS、平板、Web 和 Desktop 都先实现这个默认主题；不展示 Honey / Mint / Night / Neutral 选择器，也不因操作系统为深色就自动换主题。

多主题仅预留。旧版四主题、旧 Theme enum、参考板与偏好值保留供后续使用；不删除有用历史代码，也不把保留它们作为本期必须维护四套 UI 的理由。

### 1.1 默认视觉映射

以下来自当前手机浅色 Token 与交接，不是新调色方案。实际实现前读取最新节点／变量，差异由 C02 同步到权威视觉合同。

| 语义 | 当前设计参考 | 用途 |
|---|---|---|
| background | `#F7F8FA` | 页面底色 |
| surface | `#FFFEFC` | 内容表面 |
| text.primary | `#202329` | 主要文字 |
| text.secondary | `#616771` | 次要信息 |
| action.primary | `#C84B3D` | 实心主动作 |
| action.onPrimary | `#FFFEFC` | 主按钮文字 |
| emphasis.text | `#9E382A` | 强调文字与部分次动作 |
| emphasis.surface | `#FFF1EB` | 选中／轻强调表面 |
| control.border | `#838A94` | 表单边界参考 |
| focus | `#626873` | 焦点参考；2px轮廓及3px间隔沿用选定稿 |
| consumer.radius | 16 | 卡片、输入与消息容器 |
| action.size / radius | 高48／圆角24 | 手机主次动作胶囊；具体组件以最新稿为准 |
| 字体 | Noto Sans SC / Manrope | 中文与主体内容／品牌；不得用旧 Outfit / Inter 覆盖新稿 |

默认主题与旧 Honey 不同，不能把“先默认主题”实现为调用旧 Honey Palette 后结束。市场、领养、消息也不强制使用旧 Mint 或其他主题。

### 1.2 扩展预留的最小范围

- 各端组件读取语义 Palette、Typography、Spacing、Shape，不在每个页面散落业务颜色；平台保持相同角色名与一份映射清单。
- 当前只激活一个 `DesignDefault` 的本地样式配置；该名字是客户端概念，不直接上传为服务器 theme 枚举。
- 历史服务端／本地 theme 值仍可保存和读取为迁移信息，但本期不参与实际渲染。不自动把 old night 变成启动黑夜，也不把服务器旧 theme 字段改写为未知值。
- 明确 `effectiveAppearance` 与 `legacyThemePreference` 的区别；账号同步不得因为使用默认样式就清空历史偏好。
- 可为未来主题解析器保留接口／构造参数，先仅提供默认实现。无需提前写四套资源、切换动画、选择器、系统联动和暗色截图。
- 未来启用多主题时另做完整 Token、组件状态、对比度、图片与系统栏验收；不能仅替换背景色。

现有 `mnd_theme`、`meow.theme` 等键和 Honey／Mint／Night／Neutral 的兼容别名不能随手删除。新客户端的实际偏好迁移在 C05 中统一设计，禁止多端作者各写一次互相覆盖的迁移。

## 2. 视觉权威迁移

本轮用户选择以手机样式为目标，跨端参照[全量交接](../design/figma-study/CROSS_PLATFORM_FULL_REVIEW_2026_10_20.md)和[本轮修订](../design/figma-study/DESIGN_CLOSURE_2026_10_21.md)。现有 [Stitch工程合同](../design/MND_UI_ALIGNMENT_GUIDE.md)仍说明旧客户端，实施时由 C02 记录默认 Token、字体、导航、组件和历史主题保留方式，并更新入口指向。

这份规划不等于已经改过生产合同；也不能让 Gemini 根据旧 AGENTS 直接恢复到旧多主题方向。用户后续授权按本套文档实施时，先完成明确的合同映射，再改业务页面；不重复设计另一套视觉风格。

所有原生画板只是参考尺寸；原56张已为历史代表稿，全量映射和新增状态也不是运行自适应证明。按钮、权限和状态以业务合同为准，设计稿固定成功／失败示例不能直接写死到生产逻辑。

## 3. 各端独立适配

### 3.1 可共享与不可共享

可共享：选中对象ID、会话身份、筛选语义、业务草稿、当前服务端版本、权限与功能状态。

各端独立：可用窗口测量、单／双／三栏、Insets、安全区、折叠缝、焦点、滚动、手势、键盘、hover、菜单和返回行为。Android 平板和 iPad 不共用一套业务 Composable；Web 平板也不复用原生布局代码。

### 3.2 Android 的窗口策略

使用实际可用窗口宽高及折叠状态。官方宽度档位以 `<600dp`、`600–839dp`、`>=840dp` 等划分，且不等同设备是不是平板；可用高度也会影响是否适合双栏。[Android窗口尺寸文档](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)

本项目在这些信息上作下列布局决定，库 API 按锁定版本实现，不照抄当前最新文档里的函数名后假定旧依赖能编译。

| 情境 | 项目策略 |
|---|---|
| 窄窗口 | 手机式单页任务；详情返回列表；底部主要动作可见 |
| 中等窗口 | 双列内容浏览；长表单单列居中；消息按最小可读宽度决定单页或列表＋会话 |
| 宽窗口且高度充足 | 主从领养；消息有余量再显示上下文；发布可并列预览 |
| 宽但高度很低／键盘占用 | 收起上下文和非必要预览，保持输入与提交入口；不机械维持三栏 |
| 折叠／铰链 | 不跨不可用区域放按钮或正文；各面板保留内容和焦点；不重复创建 Store |

验收边界包括599/600、839/840附近窗口，不只看390和834；系统返回先退出局部编辑／详情或关闭覆盖层，最后才退出当前主任务。

### 3.3 iPhone 与 iPad

iPad 读取当前 Scene 内容区域，不以 `UIDevice` 的类别或整块物理屏幕宽度决定布局。834×1194与1194×834是视觉基准，744宽提供单页阅读参考，不是只支持这三个固定尺寸。

| 情境 | iPad 策略 |
|---|---|
| 竖屏 | 社区双列；长详情／申请优先可读宽度；消息收起第三栏 |
| 横屏 | 领养列表＋详情；消息有足够宽度时加宠物上下文；发布编辑＋预览 |
| 窄分屏／小窗口 | 回单页阅读和明确返回；关键动作保留；已选对象和未提交草稿不丢 |
| 浮动／拆分／外接键盘 | 输入区域跟随真实 Insets；不写死底部键盘高度；表情面板可关闭且不吃掉焦点 |
| 多Scene（若纳入） | 每窗独立路由与编辑上下文，共享会话协调；重复编辑按草稿版本处理 |

Compose 导航、UIKit 系统面板和边缘返回手势只由一层决定；薄 SwiftUI 宿主不能再套一个独立业务 NavigationStack。系统 Picker、Apple 登录和地图的呈现按iOS能力处理，不能画一个相似弹窗代替真实系统授权。

### 3.4 Web 与 Desktop

Web任务正文最大820，外层导航与工作区可更宽；1248仅为早期外层参考，不作为任务正文验收值。390为移动网页、744／834为平板参考、1194为横屏、1440为桌面；另外检查320和大字。浏览器缩放后按实际CSS宽度重新布局，按[现行自适应合同](../design/figma-study/CROSS_PLATFORM_ADAPTIVE_CONTRACT.md)验收。

Desktop 按当前窗口内容宽度逐步从三栏收为两栏／单页；不能通过最小窗口宽度禁止用户进入窄布局来假装适配完成。桌面输入、快捷键、焦点、滚动与拖放独立实现；任意标题、长昵称和多语言文案不能挤掉主要操作。

## 4. 功能布局要求

| 功能 | 手机／窄窗口 | 宽窗口 | 保持不变的状态 |
|---|---|---|---|
| 社区 | 内容列数按可读宽度变动，触控目标不缩小 | 多列卡片，阅读宽度受限 | 筛选、分页和已浏览位置 |
| 领养 | 列表与详情分别进栈 | 列表＋选中详情，次要信息可折叠 | 宠物ID、申请上下文、详情新版本 |
| 消息 | 单会话／独立列表，输入贴近底部 | 列表＋会话＋可收起上下文 | 会话ID、草稿、滚动锚点、已读边界 |
| 发布 | 表单纵向，成功图片与失败项保留 | 编辑＋预览，多图可拖排 | 正文、媒体顺序、受众、同步状态 |
| 预约 | 当前有效版本与提案分区 | 对照新旧内容与历史 | 生效版本、提案版本和双方确认 |
| 走失／认领 | 列表与私密表单分路径 | 公开案例旁放私密线索表单 | 公开／私密边界、案例ID、证据用途 |
| 我的／多宠 | 宠物切换和任务入口 | 更丰富近况与任务布局 | 宠物选择、角色与独立可见范围 |

## 5. 运行验证之前的静态检查

- shared不引用Android UI、UIKit UI、DOM或平台导航对象；iosUi不依赖androidApp。
- 新页面默认主题来源清楚；没有系统深色自动切换或旧四主题选择器；历史偏好迁移不会被默认样式清空。
- 实际请求使用v2并处理正确Envelope；新命令失败不回退v1／静态演示。
- 所有提交绑定真实权限／版本／进行中／失败恢复；登录返回仅恢复编辑。
- API secret、用户材料、令牌不进入日志、路由、截图、公开资源或普通偏好存储。
- 原生与Web各自的事件处理、Store作用域及请求取消清楚；布局切换不创建第二个业务提交者。
- 文档链接、JSON、UTF-8无BOM、diff空白和所选依赖配置做静态核对。

脚本名含check/validate不代表无副作用，运行前先读源码。上述静态项可在无运行授权时完成，不代表工程编译通过。

### 6.1 自动化测试范围

共享层重点写有价值的状态／边界测试：会话轮换并发、取消传播、409不盲重放、私密缓存清理、分页空页继续、同幂等键重试、两种协作角色权限、预约有效版本与提案、草稿账号隔离。

平台测试验证真正的平台差异：Android状态恢复和权限回调，iOS宿主与键盘／回跳，Web大ID／路由／Cookie媒体，Desktop窗口／输入法／凭据不可用。测试不能仅重复实现内部函数；低影响文案调整不另写镜像测试。
