## 安全与恢复

`MobileFeatureStore.kt` 是同一业务 owner 的扩展，不持有 Android UI。功能表单按路由写入 `noBackupFilesDir/mnd-workflows`，评论／聊天写入独立 `mnd-replies`；游客分别使用独立 namespace，不复用账号 1 的目录。账号变化立即清空内存，再读取对应账号文件，只保留需要重新授权读取的对象指针。密码／验证码／用途证明不进入表单快照、SavedStateHandle 或普通偏好。受限结果与本机草稿只保存不含 token 的引用，安全附件按事项关联原会话，真正能力保存在既有安全 vault。照片先写原字节再上传；已上传 ID 写入 manifest 后才回收私有副本。失败与进程恢复不自动上传／提交；原照片、顺序、基准版本、结果未知标记和原请求编号一起恢复。

本机快照以 revision 比较后原子写入；跨窗口冲突不覆盖已保存版本，当前输入保留，可重试保存或明确放弃未保存输入后重新读取。退出与敏感账号变更／注销导致的退出清理本账号私有文件，递增空快照阻止旧窗口写回；受限查询能力不随普通草稿清理。恢复入口在“待核对操作”的本机表单／消息草稿中。敏感提交前也先落盘原请求引用，成功后清理相应表单；用途 proof、OTP、密码不落到草稿。

写操作先核对不可变输入和版本；409 保留输入并要求明确放弃旧修改后重读。结果不明不重建请求；支持回执的命令按原编号核对／重试。没有幂等回执的旧接口若发生不明结果，会保留未知并关闭该页重复提交，不能把刷新一次当作“原请求一定未到达”。确认成功后跳到真实记录，避免留在新建表单重复创建。

图片转码先读取 JPEG／PNG 中的来源标识，仅将允许的 AIGC JSON 字段写入规范化结果，相机／位置元数据不复制。无法完整保留的标识或带标识的其他输入格式拒绝转换，不通过删标识绕过服务端判断。事实材料仍由服务端校验；本批没有执行图片回归或供应商联调。

## 必要接口修正

`inbox-summary` 原来只有数量，不能可靠定位首条未读；现在添加受原会话权限与已读回执约束的 `direct_first_unread`／`group_first_unread`。忽略本人发出的消息，全部读完不保留位置，GET 不核销未读。Android 默认从首条未读读取，提供明确定位和读取较早历史；新消息不会强拉已有滚动位置。OpenAPI响应与共享 `InboxSummary` 同步，增加未执行的 `inbox_position_test.go` 回归源码。

`internal/mobile/rescue.go` 的 `Introduction` 原来统一要求所有照片属于操作者，导致已获授权协作者连保留该宠物原有照片都会失败。现在仅允许保留**当前宠物已经附带**且 ready 的照片；新增照片仍须属于操作者，公开介绍不得挂私密材料，AI 生成材料不作为事实照片。邀请撤销、原版本、独立健康字段及领养决定权限继续校验，没有开放其他宠物媒体。

新增 `LocalWorkspaceDraftsTest.kt` 回归源码覆盖账号／游客隔离、原编号／用途／版本恢复、manifest 写失败保留旧稿、退出 tombstone 拒绝旧窗口、凭证／跨服务与路径注入拒绝；没有执行。

增加 `internal/mobile/introduction_collaboration_test.go` 回归源码，覆盖保留本对象媒体、拒绝其他对象／私密／生成材料、新增自己的公开照片和撤销后失权。**没有运行测试。**

照护协作 UI 则直接使用 `care_updates` 的既有授权合同，未扩大 `adoptions/{id}` 的读取权限。
