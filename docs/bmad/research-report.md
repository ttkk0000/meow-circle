# M&D 中国市场策略与产品判断

版本：2.0｜更新：2026-10-15｜性质：产品策略评审稿

证据：用户买猫经历与本会话澄清、现有源码、公开产品规则。市场数据单独标注年份；本文不构成用户规模验证。

## 1. 当前结论

M&D / meow & doggie 继续以交流和领养为核心，增加“找猫”中的商业售猫与有偿转让信息，优先解决渠道真实性。个人、商家、猫舍和公开关系的代理均可参与。家庭饲养、商业经营和有无中介都不能单独决定可信度。

产品价值建议表述为：

> 看清猫、发布者和接待方，出发前确认地点与费用，让领养和买猫过程有据可查。

“真实披露”是准入与持续治理要求。平台只对已经核对的具体事项说明范围、方法、时间和局限，不使用“绝对真实”“保证不被骗”“认证无病”等承诺。

## 2. 已确认方向与方案假设

| 类型 | 内容 | 依据 |
|---|---|---|
| 用户已明确 | 交流与领养为主，交易先次要 | 本会话市场定位要求 |
| 用户已明确 | 允许商家卖猫，不要求家庭饲养 | 本会话最新澄清 |
| 用户已明确 | 要防身份借用、隐瞒中介、虚假地点和被带往其他商铺/猫厂 | 用户买猫经历 |
| 产品建议 | 一个 App，社区、领养、找猫、消息、我的五个入口 | 便于共享信任记录；导航仍需映射 Stitch |
| 规划假设 | 首轮只做信息、核验、预约、反馈与争议记录，不代收猫款 | 控制首版工作量；支付尚未决策 |
| 待验证 | 用户是否愿意在平台预约并提交到访反馈，供给方是否愿意披露关系 | 尚无访谈与实测数据 |

“交易次要”在本方案中表示暂不扩张完整支付、订单、物流和泛用品商城；售猫渠道真实性需要进入首轮验证，才能检验用户提出的痛点。

## 3. 重新定义问题

### 3.1 需要解决的具体任务

买猫用户在短视频、内容帖子或群聊中找到线索后，常常无法提前确认：

- 发布者是猫的持有人、商家员工、代售方，还是只负责引流的人；
- 猫目前在哪里，约见地点是否就是所说地点；
- 照片里的猫是否可看、是否仍在，到了现场会不会换猫；
- 接待方和预计收款方是谁，为什么与发布者不同；
- 展示价之外是否还有必须购买的用品、服务或持续费用；
- 发生变更时自己有没有拒绝出口与事前信息记录。

以上是来自用户经历的待验证问题框架，不能由一个案例推断全国发生率。

### 3.2 平台接受和约束的行为

| 可以接受的安排 | 必须披露与核对的关系 |
|---|---|
| 门店售猫 | 商户主体、发布人员授权、实际接待门店与售后责任方 |
| 猫舍或繁育者发布 | 当前照护、来源说明、可提供的繁育/健康材料 |
| 商家代售 | 委托关系、实际照护方、代理/服务收费与责任方 |
| 个人转让 | 转让关系、当前照护、价格和条件 |
| 在合作医院看猫 | 医院是约见场所还是销售方，猫如何到场、谁负责 |
| 预约后主动换猫 | 创建新的猫与报价确认，不覆盖原记录 |
| 救助机构收取合理支出 | 真实列明费用与凭据，不能借“免费领养”隐瞒捆绑消费 |

需要治理的是虚假、遗漏、冒用和未经确认的变更。高频发布、多品种、多地点本身只能触发复核，不自动证明违规。

## 4. 市场依据及中西对照

### 4.1 中国市场数据说明机会背景

2026 年发布的行业白皮书统计：2025 年城镇犬猫消费市场为 3126 亿元，犬猫数量约 1.26 亿只。这说明养宠消费基础，但不能换算成买猫成交市场、领养需求量或 M&D 可获得用户数。[宿州市政府发布信息](https://www.ahsz.gov.cn/zwzx/bmdt/196205481.html)

目前缺少足够可靠、口径一致的公开数据来估算“被中间人引导看猫”的人数、欺骗率或单独市场规模。本版撤下此前用宠物总消费支撑领养/找猫增长的推断。

中国的获客方案建议以内容分享和本地合作为起点，验证从帖子/群聊链接到详情、预约和反馈的实际转化；现阶段不宣称已经证明某个渠道最有效。

### 4.2 美国领养平台：学习档案与流程

Petfinder 的成员规则要求真实维护联系方式、当前照护地点和宠物描述，并限制为营利售猫犬等行为。其机构与商业边界属于该平台选择，不能直接当成 M&D 禁止商家售猫的依据。[Petfinder 成员规则](https://member-cms.petfinder.com/tos)

Rehome 将档案、申请审阅、见面和转移确认串成流程。M&D 可以借鉴其任务衔接，但不照搬其收费和机构条件。[Rehome 流程](https://rehome.adoptapet.com/how-it-works)

### 4.3 英国购买规则：学习具体来源检查

英国政府购买指南强调核对繁育/销售相关信息、医疗资料和实际环境。英国对幼猫幼犬供应链有本地限制，M&D 在中国允许已披露代理是独立产品方向，不能把英国规则描述为全球通用，也不能将英国指南当作中国准入法律依据。[英国政府购买与领养指南](https://www.gov.uk/guidance/buying-a-cat-or-dog)

因此，本报告只对照特定国家和产品的具体机制，不再把“中国”和“西方”概括成两个统一市场。

## 5. 差异化及竞争判断

本阶段的竞争替代是用户目前使用的帖子、群聊、电话和线下带看。M&D 应通过案例验证三个收益：

1. 出发前能否看懂发布者与实际接待方的关系；
2. 发生地点、猫或报价变更时，能否发现并重新决定；
3. 出现争议时，能否恢复双方当时确认的信息。

通用社区带来曝光，聊天工具承接沟通。M&D 的机会在于把发布信息和线下接触之间的重要承诺保存下来。这个优势需要有愿意维护资料的供给方和人工处理机制，单靠页面和认证图标不能成立。

## 6. 首轮产品范围

### 6.1 共享基础

社区、领养和找猫共用账号、宠物信息、主体关系、分项核验、会话、举报和公开履约记录。一个商家可以做救助，也可以销售，但每条信息必须标注具体性质与费用。

### 6.2 领养路径

保持独立的领养说明、必要申请、沟通、试养/交接和回访。没有繁育资料的救助猫允许如实标为未知，不为过表单而编造父母信息。

### 6.3 找猫路径

发布单只猫、披露主体与代理关系、展示价格与必付项、预约确认、变更再确认、到访分项反馈、争议与申诉。

买猫用户不填写整套领养家庭调查。付款服务待后续决策，平台记录的“预计收款方”属于卖家声明；若未接入支付，不能标记成“实际收款已验证”。

### 6.4 后续能力

机构协作、详细回访自动化、医院材料验证、微信小程序、服务合作可在闭环验证后增加。完整支付担保、赔付、跨城运输、泛商品市集应分别立项，不随售猫信息入口自动纳入。

## 7. 核验策略及能力边界

| 手段 | 可支持的判断 | 不能推导的结论 |
|---|---|---|
| 身份与经营材料 | 账号与主体建立核对关系 | 单只猫的所有权和健康 |
| 人员授权和代售证明 | 某人被授权发布、接待或代理 | 永久不存在未披露参与者 |
| 限时随机任务视频 | 提交者近期接触所示猫和环境 | 家养、亲生、无中介或无疾病 |
| 定位、EXIF、到访码 | 辅助核对时间地点或预约关联 | 单独证明实地到访与真实成交 |
| 预约快照与版本记录 | 双方确认过哪些具体事项 | 现实中一定履行 |
| 买家到访反馈 | 有上下文的一致/不一致报告 | 平台亲自实地验证 |
| 医疗文件 | 某时间、某项目的材料或核验结果 | 永久健康保证 |

核验应分层、按风险补充。替代视频方式、材料脱敏、过期复核和申诉同样属于产品设计，详见[真实性与披露规范](../design/MND_TRUST_AND_DISCLOSURE_SPEC.md)。

## 8. 冷启动与可行性验证

### 8.1 推荐首城方式

选择团队能够到场核对并处理争议的城市。首批招募覆盖救助、个人转让、门店、猫舍和公开代理，不只招“家庭卖家”。

先回放约 10 个历史或真实案例，包含换地点、员工接待、医院看猫、到场换猫、加价和隐瞒代理。完成访谈和可用性走查后，再确定档案数与用户量目标。

### 8.2 准入与运营

首批供给采用邀请与人工审核。是否上架取决于材料、关系与信息是否达到发布门槛，不取决于是否愿意付认证费。审核与暂停必须允许补充和申诉，不能凭举报数量直接公开定性。

### 8.3 验证顺序

- 先证明表单能还原信息差和变更。
- 再证明双方愿意预约和反馈。
- 然后衡量一致率、投诉处理与供给维护成本。
- 最后讨论扩大城市、收入模式和支付闭环。

之前的“12 周必上线”“10–20 家伙伴、100–200 只猫”为早期规划假设，本版不把它们作为已有资源或交付承诺。

## 9. 成功指标

两条业务结果分别统计，避免买猫量掩盖领养效果：

- 领养：完成双方交接确认且 30 天回访有效的领养数。
- 找猫：有完整确认快照、买家提交反馈且关键事项均一致的到访数。

质量护栏包括：到访反馈覆盖率、未反馈比例、身份/猫/地点/费用分项不符率、变更重新确认率、争议处置时间、重复违规和申诉改判率。

所有一致率都以明确有反馈的样本为分母，同时公开样本量和反馈覆盖率。“没人投诉”和“对方未回复”均不能算一致。试点目标属于内部假设，定义见 [PRD](prd.md)。

## 10. 收入与平台责任判断

可以研究商户资料管理、预约管理和机构协作工具；付费不会提高核验结论，也不会使未达准入门槛的账号获得曝光。推广需明确标记并受同一资料要求约束。

首期不代收款只是范围假设，不代表平台没有经营者核验、内容管理或消费者保护义务。《电子商务法》第 27 条包含入驻经营者身份、地址等核验登记要求；2026 年生效的平台规则办法也涉及信息披露和个人信息责任。具体适用范围需结合实际服务确认。[电子商务法](https://www.cac.gov.cn/2018-09/01/c_1123362506.htm)、[网络交易平台规则监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2026/art_85b474fc5a08494bb60ca6a280b98d7d.html)

业务规则不能只强调“用户自己交易、平台不负责”。首轮必须提供证据保存、投诉受理、必要暂停、申诉和处理结果。

## 11. 与现有代码的关系

2026-10-15 的静态依据为本地 main 分支 `e4164ff` 及当前工作树；存在其他未提交的 Android/iOS 工作，本轮仅整理文档。

- 已有 `AdoptionPet`、简单申请、社区、消息、举报、订单等基础，不代表已实现主体链路核验。
- 当前宠物模型以宽泛 `health` 与 `status` 表达信息，不足以支持分项核验与业务状态。
- 原 `Community / Adoption / Trade` 模式与 Stitch 旧导航均为现有方案；统一导航属于本版设计提案，尚未落地。
- 新增可信找猫需要预约、快照、变更、授权和证据模型；不宜直接套用用品订单。
