## 1. 体验目标

用户应能在出发前回答：这是什么性质的信息、谁发布、谁照护、谁接待、在哪里见、总共要付什么、发生变化时能否退出。

交流与领养保留核心地位。找猫提供明确标注的出售/有偿转让信息。不同任务共享账号、消息与核验记录，用户无需先选择一套 App 模式。

商家、个人、员工和已披露代理均可参与；四方主体或多个地点不同可以合理存在，页面需要解释关系，不能直接显示为异常。

## 3. 全局导航与入口

现行导航：“社区 / 领养 / 发布 / 消息 / 我的”。互助和出售分支从相关上下文进入；出售明确标注“出售与有偿转让”，不让用户误以为是领养的换名入口。

| 入口 / 分支 | 位置类型 | 首要任务 | 发布动作关联 |
|---|---|---|---|
| 社区 | 五主导航 Tab 1 | 日常、关注流、宠友圈（双向好友）、同城互助、救助日记、安家故事 | 触发“发动态 / 走失拾获求助” |
| 领养 | 五主导航 Tab 2 | 同城领养筛选、救助方资料、可信找宠（出售/有偿转让）上下文分支切换 | 触发“发布领养 / 发布出售与转让” |
| 发布 | 五主导航 Tab 3 | 统一任务分流器（发日常动态、走失/拾获互助、送养/领养、出售/有偿转让）及草稿箱恢复 | 核心发布向导主入口 |
| 消息 | 五主导航 Tab 4 | 私信与群聊、互动提醒、系统与业务通知三分类；顶部公开群发现与好友申请入口 | 无独立发布模板 |
| 我的 | 五主导航 Tab 5 | 多宠物档案、双类协作、申请、预约、回访、收藏、角色工作台与规则/安全中心 | 按权限管理已发布记录 |
| 同城互助（走失/拾获） | 上下文分支 | 武汉/上海走失求助、拾获招领、粗精度街区地图与私密目击线索投递 | 复用发布向导“走失/拾获”模板 |
| 可信找宠（出售/转让） | 上下文分支 | 查看明确标注“出售与有偿转让”的单宠披露、完整报价必付项与看宠预约 | 复用发布向导“出售/有偿转让”模板 |

发布为现行五项导航之一，页面内发布入口复用同一向导；出售与互助是上下文分支，不扩成第六个底部Tab。登录、主题切换与用户身份不改变整套导航。商业广告标记与领养分发独立。

旧三模式设置在迁移时保留兼容数据，但不再作为新用户的必经步骤。历史订单仍有受控查询入口，不进入找猫首轮主任务。

## 4. 屏幕规格

### UX-01：首页与社区

- 顶部保留 M&D 与 meow & doggie，猫为默认情感中心。
- 关注、本地及内容分类是信息筛选；不得用筛选切换整套 App。
- 领养和出售关联卡始终显示性质、状态及主体展示名。
- 商业推广不能伪装救助故事；无对应内容时显示真实空态。
- 演示、离线缓存和实时内容可区分，不以虚构反馈或认证填空。

### UX-02：领养/找猫列表

两种列表复用组件，但字段与动作不同。

| 信息 | 领养卡 | 找猫卡 |
|---|---|---|
| 性质 | 救助领养/个人送养 | 出售/有偿转让 |
| 主要信息 | 城市、年龄、健康自述、照护要求 | 具体猫、区域、主体类型、价格与费用说明 |
| 关系 | 救助方/当前照护方 | 直接发布/员工/代售或代理 |
| 核验 | 具体项目及有效状态 | 具体项目及有效状态 |
| 动作 | 查看详情、申请领养 | 查看披露、预约看猫 |
| 不可用 | 已暂停/已安家 | 已暂停/已预留/已转让 |

“家养”“无中介”可以是发布者待核对的自述，但不能直接变成平台信任章。价格不明或必付项缺失时不能以低价可预约卡片展示。

### UX-03：详情与披露

从上到下排列：

1. 单只猫照片、稳定名称、可用状态、领养或出售性质；App内视频为后续范围，外部人工材料渠道独立处理；
2. 基本档案与健康信息，未知项明确；
3. 谁发布、谁照护、谁接待，以及员工/代理关系；
4. 当前区域、约见场所类型与关系说明；
5. 价格与必付项，或领养条件与合理支出；
6. 分项核验，点击查看方法、日期、范围与时效；
7. 来源/救助时间线、交接与责任约定；
8. 底部联系与申请/预约动作。

主体关系与必付项应在主内容区可见，不放在免责文本或长折叠段底部。证件、原始视频和私人精确住址不公开。依法需公示的经营信息使用独立字段。

### UX-04：发布向导

按任务分步：“信息性质 → 单猫资料 → 主体与关系 → 场所 → 费用/条件 → 材料 → 预览”。

- 个人、商家、救助和代理按需显示字段，代理补充授权与收费。
- 可保存草稿；每步明确缺项，提交时滚动/聚焦首个错误。
- 不强求救助猫母猫资料，也不允许商业繁育者把未知写成已核验。
- 拍摄任务提供人工视频等替代路径，避免暴露家庭门牌与成员。
- 预览必须接近消费者看到的内容，包括未核验和未知标签。

### UX-05：分项核验详情

每项显示“事项、对象、材料状态、方法、核验日期、有效期、结论边界”。例如“近期猫咪视频已审阅”不能改成“真实家养认证”。

过期：显示日期与重新提交入口。待补充：显示具体缺项。存在争议：说明该项目正在复核，不能把整份档案全部标成已证伪。

### UX-06：预约确认

页面摘要包含具体猫、接待方、代理关系、地点、时间、总价与必付项、预计收款方和责任约定。

- 双方各自明确确认同一版本；不以阅读或聊天消息替代。
- 私人精确地址在必要的确认流程中按需授权，不放入分享链接。
- 只把卖家声明的预计收款人称为“预计”，不提前展示付款已验证。
- 未完成关键披露时返回缺项，不跳转外部支付。
- 主动作“确认预约”；次动作“需要修改”与“取消”。

### UX-07：关键变更

用可读对照逐项显示旧安排与新安排，如“原门店 A → 合作门店 B”“原总额 → 新总额”。

新增已知疾病、健康声明纠正、交接与售后责任改变，同样需要重新确认，不能只发普通通知。

新提案待双方确认，原有效安排与提案分别展示。动作是“接受此提案”“拒绝此提案”“提出修改”；“取消整个预约”和“报告风险”独立呈现并说明影响。拒绝提案不取消原安排，未回复不接受提案，不把拒绝记为失约。

普通改约保留原有效版本并单列提案，提案到期只结束提案。具体安全风险另走safety_hold，页面明确“先不要按原安排出发”，给取消／报告／修改出口；解除需核对并双方确认新有效版本。恢复旧内容也新建提案。普通取消与未到访分别记录，详见安全合同SC-AP。

现场主动换猫建立新的具体猫确认，原预约仍可反馈。这能区分合理换选与不知情调包。

### UX-08：到访与交接反馈

到访后问“猫、接待方、地点、费用是否与确认一致”，每项可选“一致 / 不一致 / 不确定”。

- “未到访”“对方取消”“到了但未成交”都是有效结果。
- 有到访码仅表示关联预约，不表示平台实地见证。
- 未提交反馈保持缺失；卖家不能替买家填写。
- 可上传脱敏证据；不一致不自动公开指控。
- 成交/交接另行确认，不用到访评价代替付款事实。

### UX-09：领养申请、交接与回访

领养申请仅收集匹配必要的家庭摘要，买猫用户不走此页。申请可补充、撤回、拒绝与过期，结束状态解释清楚。

同宠物可有多候选，但只能一段独占试养／交接；其他申请转候补。退养求助继续到双方安排接回、单方待确认、双确认接回或人工争议协助；接回后新发布重新核对。不得把“求助已发送”显示为安全接回完成。未成年人申请的线下签约由成年人自己的账号办理，细则见安全合同SC-AGE／SC-AD。

约见复用地点与变更确认规则。试养可选；双方确认交接后才进入回访。R1 支持 30 天回访与人工提醒，7/90 天自动化属增强能力。

回访默认私密；生成安家故事前另行预览和授权。出现退养、走失或重大健康求助进入私密处理，不默认发到信息流。

### UX-10：会话与任务

会话顶部显示具体宠物、信息性质、申请/预约编号、当前阶段和版本。普通聊天仍可用。

同时讨论两只猫时分清上下文；关键确认采用单独动作。发送中、失败、重试、未读和通知入口可辨；重试不重复发消息。提醒正文不含敏感地址与证件。

### UX-11：投诉与申诉

无预约或无码也允许报告。表单先选类型，再关联信息和可选证据。提交后给编号、受理状态、补充入口与预计响应方式。

后台区分待核实、报告获支持、报告未获支持、无法判断、申诉中和改判。“未获支持”不等于证明对方没有欺骗。被处理者可以补充；举报人不被公开。公众看到的结果经过脱敏，不显示未核实“骗子”标签。

### UX-12：后台与工作台

商家与救助工作台位于“我的”；审核与权限管理在独立 Admin shell。队列显示待办、等待时长、材料版本、当前责任人和允许动作。

暂停/撤销核验/封禁前显示对象、理由和影响。高风险材料访问留痕；平台执行者不能随意导出完整家庭资料或金融信息。

### UX-13：关注、宠友圈与公开群目录

- **单向关注与求助订阅**：用户个人主页与宠物档案提供“关注”按钮，走失/拾获详情提供“订阅进展”；操作即时生效，不向对方发送好友审批请求，也不授予查看对方私密“宠友圈”的权限。
- **双向好友与宠友圈**：发起好友申请时可附带说明（需先通过交流手机号与年龄门禁）；双方确认成为好友后，可在社区顶部切入“宠友圈”子流，查看与发布仅双向好友可见的动态，并支持按好友设置免打扰、宠友圈可见范围、解除好友或拉黑。
- **公开群目录与群管理**：从社区互助区或消息页顶部可进入同城/主题公开群目录，卡片展示群名称、物种/城市标签、群性质与入群规则；需审核群组提交申请后展示 `待审核` 状态；群设置页要求群主在退群前必须先通过“移交群主”选择器完成权限交接。

### UX-14：多宠物、其他允许物种档案与双类协作

- **多宠物切换与物种支持**：“我的”页面与宠物主页支持横向切换同一用户名下的多只宠物（猫、犬及兔兔、仓鼠、豚鼠等合法伴侣物种），每只宠物拥有独立的成长日记、相册、疫苗/驱虫时间线与关联动态，切换时状态严格隔离。
- **介绍协作者 vs. 照护协作者**：在单宠档案管理页提供“协作管理”，邀请时必须明确勾选角色类型并向被邀请方展示权限说明卡：
  - **介绍协作者**：仅显示编辑图文介绍、上传日常相册与助宣草稿入口；隐藏健康核验提交、申请审批与交接确认按钮。
  - **照护协作者**：可记录日常饮食/照护日志、补充近期生活视频并作为已披露接待方参与约见，但不能单方变更宠物归属或替代主所有人签署最终转让/领养协议。

### UX-15：走失/拾获互助、粗精度地图与私密线索

- **列表与粗精度地图双视图**：支持按武汉/上海城区、物种（猫/犬/其他）、类型（走失求助/拾获招领）筛选；地图视图仅渲染街区/商圈级粗精度聚合圆圈或网格（约 500m–1km 范围），不展示精确门牌图钉，防止恶意抓捕或上门骚扰。
- **私密目击线索抽屉**：点击“提供目击线索”打开结构化抽屉，填写发现时间、粗略位置描述、现场照片与状态（疑似看到/已临时留置/仅拍照），明确提示“线索仅发给求助发布者与平台安全审核员，不会直接公开在评论区”。
- **认领核对与状态收口**：拾获招领走“提交特征凭证 → 双方核对 → 确认团聚”路径；一旦标记“已找回/已团聚”，卡片与分享页立即置灰并隐藏联系方式。

### UX-16：三分类消息中心、`99+` 全局未读、快照已读与表情贴纸面板

- **三分类消息架构与未读徽标**：消息页顶部分为“私信与群聊”“互动提醒（赞/评/关注/好友申请）”“系统与业务通知（核验/申请/预约变更/安全回执）”三个固定标签；底部导航与分类标签未读数严格对齐，单类或全局超过 99 时统一显示 `99+`。
- **十分钟快照“全部已读”**：点击右上角“全部已读”弹出确认框，说明“仅清除红点提醒，不会自动替您同意待处理的预约变更或领养申请”；确认后底部或顶部常驻 10 分钟“撤回全部已读（恢复原未读状态）”轻提示条。
- **底部表情与 24 张固定贴纸面板**：聊天与评论输入栏右侧提供表情切换键，展开面板含“基础表情”与“M&D 贴纸（24 款猫狗常用情绪）”两栏；贴纸消息与评论贴纸统一在 `144×144` 方形容器内按原图宽高比居中缩放（`FIT`），严禁拉伸变形。

### UX-17：照护指南、规则中心与历史版本独立阅读页

- **端内独立阅读体验**：从首页科普卡、领养/找宠详情提示、发布向导准入说明或“我的 - 规则与安全中心”点击任意照护指南或平台规则时，进入端内独立阅读页（`guideDetail` / `ruleDetail` / `ruleHistory`），支持返回原上下文，不跳出到无导航的外部白屏网页。
- **结构化章节与版本追溯**：照护指南展示适用物种、核心准备清单、常见误区与紧急就医提示；平台规则详情顶部固定显示版本号、生效日期、适用范围与“查看历史版本及变更摘要”入口，点击可对照历次修订要点。

## 5. 通用状态与失败恢复

| 场景 | 必须反馈 | 下一步 |
|---|---|---|
| 网络失败 | 当前操作未完成，保留输入 | 重试或保存草稿 |
| 档案暂停/撤回 | 原因类别与当前状态 | 返回列表、看历史记录或举报 |
| 核验过期 | 具体哪项失效、最近核验日期 | 发布方更新，用户知情决定 |
| 预约版本冲突 | 对方已变更，原确认不能用于新安排 | 查看差异后重确认 |
| 对方未确认 | 待回复，不能显示已约好 | 提醒、改约或取消 |
| 证据不足 | 无法判定，非自动判定没有欺骗 | 补充或申请复核 |
| 权限失效 | 该项操作不可用，但原记录可按权限查看 | 重新授权或联系管理员 |
| 用户不便拍摄 | 说明可接受替代材料 | 人工视频/核验支持 |

## 6. 响应式与无障碍

- 320px 宽度内容单列，关键关系、差异、总额不靠横向表格隐藏。
- 桌面可左右显示档案与确认摘要，焦点/阅读顺序仍按任务顺序。
- 底部固定操作适配安全区、虚拟键盘与字体放大，不遮挡错误和最后字段。
- 原生触控目标 48dp/44pt；Web 关键目标采用 44px 以上的项目目标。
- 表单具备 label、字段关联错误和错误汇总；动态状态使用适当的 live region。
- 状态以文字、图标和颜色共同表达；必要正文对比度至少 4.5:1。
- 视频提供文字摘要/可用替代方式；用户无需听清音频才能完成核验。
- 键盘可完成筛选、确认、变更、举报与关闭弹窗；关闭后焦点返回触发点。
- reduced-motion 下去除非必要动画；超时任务可重新申请，不因无障碍操作较慢惩罚用户。
