# M&D 社区、领养与可信找猫 UX 规格

版本：2.0｜更新：2026-10-15｜状态：交互方案，尚未实施

需求依据：[PRD 2.0](prd.md)｜证据规则：[真实性与披露规范](../design/MND_TRUST_AND_DISCLOSURE_SPEC.md)

2026-10-16 增补：[武汉／上海冷启动、走失地图、渐进登录与权限恢复](../design/MND_COLD_START_LOST_PETS_AND_AUTH_SPEC.md)、[领养分项核验与举报处理](../design/MND_TRUST_AND_DISCLOSURE_SPEC.md)，附[四条独立流程图](../design/flows/cold-start-and-auth.html)。收到回执不等于已核实；新增页面仍为待设计／待实施，不覆盖下文已有流程。

视觉依据：Stitch V2；本轮没有改动远程设计或客户端。

## 1. 体验目标

用户应能在出发前回答：这是什么性质的信息、谁发布、谁照护、谁接待、在哪里见、总共要付什么、发生变化时能否退出。

交流与领养保留核心地位。找猫提供明确标注的出售/有偿转让信息。不同任务共享账号、消息与核验记录，用户无需先选择一套 App 模式。

商家、个人、员工和已披露代理均可参与；四方主体或多个地点不同可以合理存在，页面需要解释关系，不能直接显示为异常。

## 3. 全局导航与入口

建议导航：“社区 / 领养 / 找猫 / 消息 / 我的”。“找猫”副标题明确为“出售与有偿转让”，不让用户误以为是领养的换名入口。

| 页面 | 首要任务 | 发布入口 |
|---|---|---|
| 社区 | 日常、互助、救助日记、安家故事 | 发动态 |
| 领养 | 同城领养与救助方资料 | 发布领养/申请发布权限 |
| 找猫 | 查看来源关系、价格和可约见信息 | 发布出售/转让 |
| 消息 | 普通、领养、看猫会话，附具体上下文 | 无独立发布模板 |
| 我的 | 申请、预约、资料、回访和身份工作台 | 按权限管理发布 |

发布为页面主动作/工作台入口，避免将五项导航扩成六项。登录、主题切换与用户身份不改变整套导航。商业广告标记与领养分发独立。

旧三模式设置在迁移时保留兼容数据，但不再作为新用户的必经步骤。历史订单仍有受控查询入口，不进入找猫首轮主任务。

## 4. 屏幕规格

### UX-01：首页与社区

- 顶部保留 M&D 与 meow & doggie，猫为默认情感中心。
- 关注、本地及内容分类是信息筛选；不得用筛选切换整套 App。
- 领养和出售关联卡始终显示性质、状态及主体展示名。
- 商业推广不能伪装救助故事；无对应内容时显示真实空态。
- 演示、离线缓存和实时内容可区分，不以虚构反馈或认证填空。

### UX-02：领养/找猫列表

两种列表复用组件，但字段与动作不同。

| 信息 | 领养卡 | 找猫卡 |
|---|---|---|
| 性质 | 救助领养/个人送养 | 出售/有偿转让 |
| 主要信息 | 城市、年龄、健康自述、照护要求 | 具体猫、区域、主体类型、价格与费用说明 |
| 关系 | 救助方/当前照护方 | 直接发布/员工/代售或代理 |
| 核验 | 具体项目及有效状态 | 具体项目及有效状态 |
| 动作 | 查看详情、申请领养 | 查看披露、预约看猫 |
| 不可用 | 已暂停/已安家 | 已暂停/已预留/已转让 |

“家养”“无中介”可以是发布者待核对的自述，但不能直接变成平台信任章。价格不明或必付项缺失时不能以低价可预约卡片展示。

### UX-03：详情与披露

从上到下排列：

1. 单只猫图片/视频、稳定名称、可用状态、领养或出售性质；
2. 基本档案与健康信息，未知项明确；
3. 谁发布、谁照护、谁接待，以及员工/代理关系；
4. 当前区域、约见场所类型与关系说明；
5. 价格与必付项，或领养条件与合理支出；
6. 分项核验，点击查看方法、日期、范围与时效；
7. 来源/救助时间线、交接与责任约定；
8. 底部联系与申请/预约动作。

主体关系与必付项应在主内容区可见，不放在免责文本或长折叠段底部。证件、原始视频和私人精确住址不公开。依法需公示的经营信息使用独立字段。

### UX-04：发布向导

按任务分步：“信息性质 → 单猫资料 → 主体与关系 → 场所 → 费用/条件 → 材料 → 预览”。

- 个人、商家、救助和代理按需显示字段，代理补充授权与收费。
- 可保存草稿；每步明确缺项，提交时滚动/聚焦首个错误。
- 不强求救助猫母猫资料，也不允许商业繁育者把未知写成已核验。
- 拍摄任务提供人工视频等替代路径，避免暴露家庭门牌与成员。
- 预览必须接近消费者看到的内容，包括未核验和未知标签。

### UX-05：分项核验详情

每项显示“事项、对象、材料状态、方法、核验日期、有效期、结论边界”。例如“近期猫咪视频已审阅”不能改成“真实家养认证”。

过期：显示日期与重新提交入口。待补充：显示具体缺项。存在争议：说明该项目正在复核，不能把整份档案全部标成已证伪。

### UX-06：预约确认

页面摘要包含具体猫、接待方、代理关系、地点、时间、总价与必付项、预计收款方和责任约定。

- 双方各自明确确认同一版本；不以阅读或聊天消息替代。
- 私人精确地址在必要的确认流程中按需授权，不放入分享链接。
- 只把卖家声明的预计收款人称为“预计”，不提前展示付款已验证。
- 未完成关键披露时返回缺项，不跳转外部支付。
- 主动作“确认预约”；次动作“需要修改”与“取消”。

### UX-07：关键变更

用可读对照逐项显示旧安排与新安排，如“原门店 A → 合作门店 B”“原总额 → 新总额”。

新增已知疾病、健康声明纠正、交接与售后责任改变，同样需要重新确认，不能只发普通通知。

变化发生后，新安排状态为待确认；保留旧版本。动作只有“接受新安排”“拒绝并取消”“提出修改/举报”等明确出口。未回复保持待确认，不能自动继续，也不能把拒绝记为失约。

待确认期间旧安排暂停生效，页面明确提示不要按旧地点自动赴约；确认截止时间后显示已过期。提议方撤回变化、希望恢复原安排时仍需双方确认。普通取消与未到访结果分别记录。

现场主动换猫建立新的具体猫确认，原预约仍可反馈。这能区分合理换选与不知情调包。

### UX-08：到访与交接反馈

到访后问“猫、接待方、地点、费用是否与确认一致”，每项可选“一致 / 不一致 / 不确定”。

- “未到访”“对方取消”“到了但未成交”都是有效结果。
- 有到访码仅表示关联预约，不表示平台实地见证。
- 未提交反馈保持缺失；卖家不能替买家填写。
- 可上传脱敏证据；不一致不自动公开指控。
- 成交/交接另行确认，不用到访评价代替付款事实。

### UX-09：领养申请、交接与回访

领养申请仅收集匹配必要的家庭摘要，买猫用户不走此页。申请可补充、撤回、拒绝与过期，结束状态解释清楚。

约见复用地点与变更确认规则。试养可选；双方确认交接后才进入回访。R1 支持 30 天回访与人工提醒，7/90 天自动化属增强能力。

回访默认私密；生成安家故事前另行预览和授权。出现退养、走失或重大健康求助进入私密处理，不默认发到信息流。

### UX-10：会话与任务

会话顶部显示具体宠物、信息性质、申请/预约编号、当前阶段和版本。普通聊天仍可用。

同时讨论两只猫时分清上下文；关键确认采用单独动作。发送中、失败、重试、未读和通知入口可辨；重试不重复发消息。提醒正文不含敏感地址与证件。

### UX-11：投诉与申诉

无预约或无码也允许报告。表单先选类型，再关联信息和可选证据。提交后给编号、受理状态、补充入口与预计响应方式。

后台区分待核实、报告获支持、报告未获支持、无法判断、申诉中和改判。“未获支持”不等于证明对方没有欺骗。被处理者可以补充；举报人不被公开。公众看到的结果经过脱敏，不显示未核实“骗子”标签。

### UX-12：后台与工作台

商家与救助工作台位于“我的”；审核与权限管理在独立 Admin shell。队列显示待办、等待时长、材料版本、当前责任人和允许动作。

暂停/撤销核验/封禁前显示对象、理由和影响。高风险材料访问留痕；平台执行者不能随意导出完整家庭资料或金融信息。

## 5. 通用状态与失败恢复

| 场景 | 必须反馈 | 下一步 |
|---|---|---|
| 网络失败 | 当前操作未完成，保留输入 | 重试或保存草稿 |
| 档案暂停/撤回 | 原因类别与当前状态 | 返回列表、看历史记录或举报 |
| 核验过期 | 具体哪项失效、最近核验日期 | 发布方更新，用户知情决定 |
| 预约版本冲突 | 对方已变更，原确认不能用于新安排 | 查看差异后重确认 |
| 对方未确认 | 待回复，不能显示已约好 | 提醒、改约或取消 |
| 证据不足 | 无法判定，非自动判定没有欺骗 | 补充或申请复核 |
| 权限失效 | 该项操作不可用，但原记录可按权限查看 | 重新授权或联系管理员 |
| 用户不便拍摄 | 说明可接受替代材料 | 人工视频/核验支持 |

## 6. 响应式与无障碍

- 320px 宽度内容单列，关键关系、差异、总额不靠横向表格隐藏。
- 桌面可左右显示档案与确认摘要，焦点/阅读顺序仍按任务顺序。
- 底部固定操作适配安全区、虚拟键盘与字体放大，不遮挡错误和最后字段。
- 原生触控目标 48dp/44pt；Web 关键目标采用 44px 以上的项目目标。
- 表单具备 label、字段关联错误和错误汇总；动态状态使用适当的 live region。
- 状态以文字、图标和颜色共同表达；必要正文对比度至少 4.5:1。
- 视频提供文字摘要/可用替代方式；用户无需听清音频才能完成核验。
- 键盘可完成筛选、确认、变更、举报与关闭弹窗；关闭后焦点返回触发点。
- reduced-motion 下去除非必要动画；超时任务可重新申请，不因无障碍操作较慢惩罚用户。

## 7. Stitch 映射与验收边界

继续沿用 Honey、Mint、Night、Neutral；Outfit/Inter 与中文回退；消费者卡 16px、Neutral 卡 8px、按钮/输入 12px。全局主题跨页面保持，不强制找猫切 Mint。

本版导航与核验/预约屏是产品提案。实施前把它们映射到现有 TopBar、卡、状态 chip、详情、消息和确认弹窗；必要新屏在 Stitch 对齐后落地。不能因旧设计有 Orders 就推断首版必须实现支付。

验收走查至少覆盖：商家员工接待、公开代理、医院见猫、地点变更拒绝、现场主动换猫、隐藏必付项、未知健康资料、无码投诉、申诉改判、字体放大和键盘路径。此处为计划，本轮未执行设备或浏览器验收。
