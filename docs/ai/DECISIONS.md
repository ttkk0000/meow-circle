# 重要决定与待确认项

## 2026-10-23 · 闭环整改的实施选择

来源：用户要求根据复审先完善设计文档、最后跟进代码。以下是本次完善授权内的产品／工程细化，不伪称用户逐字段确认或真实运营事实。

- 申请周期由服务端维护，首次开放保持兼容周期0；关闭后重新开放才递增，普通介绍编辑／可见性修改不递增。每周期同申请人一份记录，重试核对原申请、本人撤回后可主动重提，新周期不复用旧确认。
- 试养／直接交接以pet为共同一致性边界；候补不自动晋升，其他家庭交接后明确结束旧申请。接回未实际双确认前不重新开放匹配。
- 接回提案的确认截止取计划接回时间；发起人提交计本人确认，对方独立接受后才生效。本人撤回／对方拒绝／过期不抹掉原有效安排或照护／求助；动作实时检查，不依赖定时器。
- 使用[闭环合同](../design/MND_PRODUCT_CLOSURE_CONTRACT_2026_10_23.md)和[当前账本](../client/CURRENT_DELIVERY_STATUS_2026_10_23.md)，保持Android优先／苹果UI后置。供应商、正式政策、实际责任人／日期及运行放行仍待真实落实，本记录不代填。

来源：用户本轮明确要求“主要先完成安卓的页面，苹果的先放着”。本阶段继续Android手机／平板页面及必要公共业务接线，保留苹果UI／宿主已有源码，暂不扩iPhone／iPad页面。服务器仅处理页面闭环必须的合同／适配缺陷，不借本轮扩运营系统或升级依赖。页面源码／静态核对和设备运行分开记录；本指令不授权编译、测试、设备、提交或推送。详见[本批交接](../client/ANDROID_PAGES_2026_10_23.md)。
