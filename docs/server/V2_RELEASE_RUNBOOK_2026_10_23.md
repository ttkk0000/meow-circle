## 2. 实施顺序与失败出口

1. 在获准隔离环境保存版本、配置项名称与数据备份位置；密钥由环境密钥管理提供，不进仓库、截图、游标或日志。先核对构件和客户端合同匹配。
2. 迁移前检查用户名／邮箱／手机号规范化冲突、原v1账号关联、已有多段活动试养／交接。冲突逐案人工核对，不自动合并账号或选领养赢家。迁移失败停止写入口，按对应迁移设计恢复；不盲目执行逆向SQL删除新数据。
3. 验证资格／用途／版本／幂等和原operation核对；缺配置保持受限。先公开读、草稿及必要权利通道，再按功能开放写入。
4. 配置API与每个job独立worker。具体变量查[environment.example](environment.example)与[worker交接](SERVER_FIRST_2026_10_23.md)。每job唯一私有状态文件；同文件不供多进程共享。URL／job／schema不符或游标损坏停止人工核对，不清零继续。
5. 验证真实媒体文件删除、外部授权撤销、消息渠道回执、案件转送与处理者／备份限制。API提交成功但worker断电时，原批可重试且副作用去重；不得批量ACK未处理事件。
6. 分功能验收并记录最小证据；先Android手机／平板，苹果后置。公开安全网页不等待完整Web。未就绪功能关闭，标明实际可用出口。

## 3. 告警、暂停与人工补位

| 观察项 | 需要区分 | 处置与恢复 |
|---|---|---|
| 未决operation／409上升 | 响应丢失、权限撤销、真实并发 | 暂停新提交、核对原键；不换键重放；按对象版本刷新 |
| Outbox／worker积压和租约过期 | 可重试、供应商不可用、未知结果 | 保留游标／原delivery键、减小开放范围；受理角色人工承接关键待办 |
| 删除／保全超期 | 主存、物理文件、处理者、受限副本 | 最小范围保全与复核；不显示全量删除完成；记录责任及下次反馈 |
| 宠物多活动安排 | 旧数据、缺约束、非法旁路 | 停止该宠物新安排，保留照护／求助，人工核对；不自动取消一方 |
| 游客受理／正式通知送达失败 | 联系方式无效、渠道失败、对方无回应 | 原案补充、实际升级／替补，不能自动认定事实或结案 |
| 推送失败／权限关闭 | 站内待办、渠道接收、设备展示、已读 | 站内任务保留，避免重复发；不把队列记录写成已送达 |

阈值及受理时限由实际试点容量核定并留配置版本；不在未经测量时对外承诺。日志只记必要请求／对象／版本／分类，不记录OTP、token、家庭／聊天／证件正文。

## 4. 恢复与回退验收

隔离恢复旧备份后，先应用删除限制／撤权／保全／审计及必要的新事件，再开放读取；不能让已删除材料重新进入搜索、公开分享或正常使用。核对宠物归属与唯一活动安排、申请周期、协议／预约有效版本、原operation与job游标、媒体引用／物理文件、受限回执。恢复失败保持隔离。

回退先关闭有问题的功能写入及相关job，保留合法读取／求助出口，保存未决操作和审计。旧客户端／旧服务不得绕过v2资格、用途或版本关卡；不以切回v1写入作兜底。数据库是否可回退需按实际迁移兼容性决定，默认不执行破坏性逆向操作。
