## 服务端与权限

独立[OpenAPI合同](../api/operations-v1.openapi.json)前缀 `/api/ops/v1`，13路径／15操作。`internal/platform/opsapi` 负责请求适配与授权，`internal/operations` 负责事务、状态转换与回执；内存仅显式开发，生产沿用已有Postgres连接池，Redis不缓存授权数据。

- 每个请求同时要求 `X-Operator-Token`、具名角色和精确环境范围。消费者Cookie、旧AdminKey、普通worker／privacy／moderator角色不能授予技术运维权限。
- `ops_viewer`：读取授权环境；`ops_oncall`：另可登记与处置事件；`ops_release`：另可准备和修改发布资料；`ops_admin`：读取身份与审计，不自动获得处置或发布权限。
- 环境固定来自服务端 `MND_OPS_ENVIRONMENT`，不接受请求体改变目标环境。账号 `environments` 必须含此环境；没有通配或默认全环境。
- 凭据仅当前Web页面内存，禁止Cookie携带、URL、浏览器通用持久存储或消费者API复用。断开、切换示例、离开页面会取消请求并清空；身份变化重建页面内容，旧响应按代次丢弃。
- 写入最多32KiB，拒绝额外对象与未知字段。原请求号、内容摘要、业务修改和最小审计同事务；相同内容重放返回原结果，换内容冲突。页面遇结果未知时冻结原内容，以原编号核对。
- 事件按版本及具名负责人推进 `pending → investigating → observing → resolved`。进入观察／结案需要证据引用；worker事件还需事件后的已确认批次，空闲、正常续接和未确认失败不能当恢复。自由文本只用于必要处置说明，禁止录入密钥与用户原始资料。

## 观测、持久化与接入

新增 `010_operations_console.sql`，创建独立 `mnd_ops_records` 及环境／类型／分页／状态／主题索引。任务结果、事件、准备记录、命令回执和审计独立于消费者表。没有修改001–009，也未应用010。运维未启用时不影响现有客户端；启用但缺010时运维读取明确不可用。

API任务入口在既有授权作业结束后记录最小结果，保持消费者租约／游标／ACK合同。仅记录任务、执行者、结果码、计数和耗时，不保存供应方正文或消费者资料。正常30秒分批续接记为 `continuation`，不会自动生成故障。失败或待重试结果生成同任务未结事件；遥测写入失败只记录错误类型，不把已经执行的业务伪称为没执行。没有宣称遥测覆盖全部历史；列表默认100条并可继续分页。

Postgres／Redis仅做2秒有界连接探针，不代表容量、复制、队列或全部健康。API只证明当前请求得到响应；Caddy／证书与外部监控没有采集时保持未知。外部通知、重试执行器、部署执行器、构件／审批／备份验证均未接入，本批无服务器命令、Docker socket、任意SQL或网页迁移入口。

迁移页动态读取源码目录和 `public.mnd_schema_migrations`，区分未回读、待应用、匹配、不一致、源码缺失、显式基线。设计示例保留原稿9份；真实源码目录当前10份，不能把示例数量当实际账本。迁移器现有顺序、事务与摘要校验继续适用。

接入时由部署方在真实环境完成：

1. 按既有迁移器应用010；本轮没有执行。
2. 在私有运行配置填写 `MND_OPS_ENVIRONMENT`，精确域名沿用 `MND_WEB_ORIGIN`，版本身份可填 `MND_RELEASE_VERSION`；空环境默认关闭。
3. 在现有Secret形式的 `MND_OPERATORS_JSON` 中人工配置具名运维账号、足够随机凭据、最小角色和 `environments`。已有6个worker身份不会自动升级，也没有生成或提交任何真实凭据。
4. 构建并启动后访问 `/app/ops` 连接账号；`/app/ops?mode=demo` 可进入明确标识的示例模式。构建／启动仍需遵循仓库单独执行规则。
