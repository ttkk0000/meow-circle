## 修复的实际缺口

此前资料删除和物理媒体清理仅检查资料请求里的保全，游客到期清理另查权利案件，上传回收又有自己的判断。拥有者提交新删除请求时，可能绕过同一附件在权利案件／核实事项中的留存；另一个资料请求也可能绕过旧请求的字段保全。

现在 `internal/mobile/evidence_retention.go` 提供同一套检查，接入资料处理、物理删除准备、游客到期及上传回收：

- 对象保全按 kind／ID 跨请求核对，包含其他参与方资料请求中的原有事项保全；个人字段仅按所属账号和字段核对。复核日期到期仍保持保全，需明确解除，不阻断无关字段／附件。
- 权利案件未结案、转送未完成或证据期限未到时保留材料；过期的未结案件进入复核。核实／举报附件在原证据有效期内同样不能被拥有者删除请求绕过。
- 新增保全只能覆盖本请求尚未清理的选定数据；自动生成的参与事项保全仅能保持其原范围或明确解除。不能保全其他账号、未选数据、已擦除字段，也不能凭空提交“解除”。已经进入物理删除的附件不能被重新声明保全或延长案件证据期限。
- 正式权利声明的用途摘要补入姓名、权利类型、附件选择，修改这些内容会使旧用途证明失配。

保全不扩大读取权限。过期但尚待复核的材料不会自动开放给运营读取；运营必须先对准确版本记录理由、责任人及延期日期。已经擦除的案件不能重新开启或恢复材料。

## 新增运营接口

| 接口 | 角色与结果 |
|---|---|
| `GET /api/v2/ops/rights-cases?cursor=0` | moderator；每页100条最小编号／版本／状态／期限，不含联系方式、姓名、正文或附件ID，读取留审计。 |
| `GET /api/v2/ops/rights-cases/{id}` | moderator；审计后的处理详情。仅证据期限有效且未擦除时返回材料正文／联系方式／附件ID；过期只返回状态，附件字节仍需既有 evidence_reader 权限。 |
| `POST /api/v2/ops/retention-expiry`，正文 `{"cursor":0}` | privacy；每批扫描100案件。仅已明确 closed、转送为 not_required／transferred、留存期已过且无对象保全时擦除案件正文与附件关联，记录时间与事件／审计。 |

游标为0表示本轮扫描结束；部署调度器下一轮从0重新扫描，复核和解除后才可能继续清理。`held` 是本批到期但仍受保护的数量，不代表自动释放。没有启动后台定时器或配置真实调度器。

案件擦除只处理该案件的联系／身份／声明／证据消息和附件关联，保留最小回执、流程、转送凭据及关系元数据；不是整条案件、物理文件、处理者或备份全量擦除。自己的照片继续按拥有者的删除请求处理；游客附件由原 privacy-expiry 转入物理清理，仍需原 media-erasure 真实文件结果。处理者／备份回执保持独立。

## 公共 KMP 状态

`DataRequestStatus` 增加已擦除对象、附件物理待处理、外部授权待处理、待处理字段、最早复核时间、复核到期、受限副本数量及 `progress_version`。字段清理完成后保存 `erased_fields`，重处理同一请求时不会再次抹掉该已处理字段。跨请求保全也纳入受限进度，查询能力仍只返回最小状态，不返回其他案件详情或责任人。

`DataRequestProgress.kt` 与 `FeatureState.dataProgress` 提供两端共用的显示状态：处理中、部分保全、事项协助、受限副本保留、完成、待核对。只有服务端分项进度合同版本1、分项无待处理／保全、外部回执完整且没有受限副本时才显示最终完成。`completed` 与分项不一致时待核对；受限备份不能显示成所有副本已经删除。旧版本或历史记录缺少分项证据时同样待核对，不自动重建请求或猜测执行擦除。

`RightsReceipt.evidence_state` 仅区分 retained／review_due／erased；erased 指本条案件正文／关联清理，不能等同附件物理删除。Android／iOS完整新状态渲染不在本批 UI 验收范围。
