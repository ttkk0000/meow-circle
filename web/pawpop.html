Post-login app modes

三大功能主题 / KMP Android UI 设计规格

这里不是新增外观主题，而是登录后的三套功能入口：宠物交流、宠物收养、宠物交易。页面用原 Stitch 索引的卡片语言表达，下面的 13 张 App 设计图继续作为视觉风格和组件来源。

3 modes + 13 refs
1. 登录成功读取本地或后端偏好 mnd_app_mode，有值时直接进入对应 App Shell。
2. 首次选择没有默认功能主题时，展示三卡选择页：宠物交流、宠物收养、宠物交易。
3. 进入独立页面栈不同功能主题拥有不同底部导航、首页内容、详情页和消息上下文。
4. 设置中切换“默认功能主题”和 Honey/Mint/Night/Neutral 外观主题分开保存，切换后重建导航栈。
Community mode

宠物交流

C
cat-firstHoney defaultsocial feed

面向猫猫日常、圈子互动和内容发布，延续现有 Feed / Profile / Messages 的 Honey 视觉语言。

底部导航动态 / 圈子 / 发布 / 消息 / 我的
页面栈FeedHome, CircleHome, ComposePost, Messages, Profile
详情页PostDetail, CommentThread, CircleDetail, PetProfile
  • 保留发布入口、推荐/最新/关注 tabs、媒体卡片、评论、收藏、关注。
  • 消息页默认上下文是评论、关注、圈子回复和私聊。
  • 空态、骨架屏、发布失败、媒体加载失败都要有同风格占位。
Adoption mode

宠物收养

A
missing modulesafety-firstnot marketplace

新增完整收养模块，面向待领养、救助进展、申请管理和救助方沟通。它不能做成 Market filter，也不能使用交易话术。

底部导航领养 / 救助 / 申请 / 消息 / 我的
页面栈AdoptionHome, RescueHome, ApplicationCenter, Messages, Profile
详情页AdoptPetDetail, RescueDetail, ApplyForm, ApplicationTimeline
  • 首页包含城市/品种/年龄/健康状态筛选、救助方标识、安全提示和待领养卡片。
  • 主 CTA 固定为“申请领养”；消息上下文使用“领养申请”，不出现购物车、支付、立即购买或交易订单。
  • 申请态要覆盖草稿、已提交、审核中、需补充、已通过、未通过、已撤回。
Trade mode

宠物交易

T
social commercetheme inheritsorders

对应现有 Market / Product / Orders 设计，但作为独立功能主题进入，底部导航和发布流程聚焦用品、服务、交换和同城交易。

底部导航市集 / 发布 / 消息 / 订单 / 我的
页面栈MarketHome, PublishListing, TradeMessages, Orders, Profile
详情页ProductDetail, SellerProfile, OfferSheet, OrderDetail
  • 分类 chips 使用 Sell / Trade / Looking For / Free / Donation，不把 Market 强制成 Mint。
  • 主动作按商品状态显示 Buy Now、Contact Seller、Make Offer、Save。
  • 订单态只使用 pending_payment、paid、cancelled、shipped、refunded、completed。
KMP route and state matrix

入口、切换和状态矩阵

场景界面要求KMP 行为
未登录保留现有登录/注册页，可在登录页底部露出“登录后选择功能主题”的轻提示。不创建 App Shell，不写入功能主题。
登录成功且无默认值进入三大功能主题选择页，三张卡必须展示名称、说明、底部导航预览和推荐标签。保存 mnd_app_mode 后进入对应 graph。
登录成功且有默认值跳过选择页，直接进入上次使用的功能主题首页。MndAppMode 驱动 root nav graph。
设置切换设置页新增“默认功能主题”，位置和外观主题相邻但语义分开。更新偏好后清空当前 tab stack 并进入新 graph 首页。
消息入口三套功能主题都保留消息，但消息列表和上下文标签跟随当前功能主题。消息详情接收 modeContext。
异常/空态每套主题必须有加载、空列表、网络错误、权限不足和操作失败状态。复用 Stitch 组件状态，文案按功能主题切换。

Implementation handoff

KMP Android 落地边界

实现时不要只在 Feed 顶部加三个按钮，也不要把收养做成 Market filter。三大功能主题需要切换整套底部导航、首页信息架构、详情页和消息上下文。

MndAppMode.community -> CommunityNavGraph MndAppMode.adoption -> AdoptionNavGraph MndAppMode.trade -> TradeNavGraph
外观主题：Honey / Mint / Night / Neutral 仍是全局 visual theme。 功能主题：Community / Adoption / Trade 是 post-login app mode。 收养模块：申请、救助、安全提示、救助方沟通必须独立建模。 交易模块：订单和支付语义只在 Trade mode 出现。
收养禁用交易语义：不出现购物车、支付、立即购买或交易订单。主动作使用“申请领养”，消息上下文使用“领养申请”。
